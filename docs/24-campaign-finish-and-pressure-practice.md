# 0.39 일반 캠페인 완료와 실패 구간 연습

개발본 0.39.0 / Android code 42 / 전투 규칙 29. 운영 서버·Play 배포와는 별개다.

## 강화 상한을 늘리는 것에 대한 판단

상한 확장 자체는 문제가 아니다. 다음 지역·새 장비 선택·새 로봇 활용처럼 추가 성장의 쓰임새가 있으면 성장과 구매의 재미를 늘릴 수 있다. 다만 기존 일반 캠페인의 벽을 해결하기 위해 상한과 비용부터 늘리면, 이미 끝까지 강화한 이용자에게 다시 반복이나 구매를 요구하게 된다.

이번에는 기존 성장의 보상을 먼저 복구한다. 대원 Lv.30·장비 Lv.20, 보급 가격·구성·구매 제한·무료 보상은 유지한다. 향후 상한 확장은 추가 콘텐츠와 함께 별도로 판단한다. 무료와 구매 경로는 같은 성장 상한을 사용하며, 구매의 역할은 더 빨리 도달하는 것이다. 모든 상한 계정의 승리를 보장하는 변경은 아니다.

## 사망 원인에 맞춘 조정

0.38 원본에서 자연 조작의 냉각 지역 패배 21판 중 8판, 중앙 공장 패배 24판 중 13판이 보스 도달 후였다. 그중 접촉 사망은 각각 6·10판이다. 일반 적 피해만 계속 낮추는 대신 보스와 충돌했을 때 빠져나갈 여유를 함께 조정했다.

| 대상 | 변경 |
|---|---|
| 냉각 일반 적 | 공격 피해 10% 완화. 방패의 정면 피해 수용률 45→60%, 측면은 100% 유지 |
| 중앙 공장 일반 적 | 기본 대비 피해 계수 0.90→0.85. 기존 소환체 8기 상한 유지 |
| 냉각·공장 보스 | 접촉 피해 25% 완화, 접촉 간격 0.75→1.1초, 접촉 후 밀려나는 거리 22→55 |
| 궤도 일반 구간 | 55→60작전의 일반 적 공격·접촉 피해 계수 1.00→0.90로 점진 완화 |
| 궤도 보스 | 추가 체력 계수 +8~24%→+4~10%, 해당 추가 피해 계수도 절반으로 연동 |
| 일반 60 보스 | 접촉 피해 계수 0.60, 접촉 간격 1.1초, 접촉 후 거리 확보 |

극한과 동일 조건 실력전에는 새 접촉 완화와 최종 지역 완화를 적용하지 않는다. 기존 후반 다른 지역의 마지막 보스는 유지한다. 보스 돌진 피해를 접촉 피해로 바꿔 계산하지 않는다.

[360판 전후 비교와 원본](reports/curve039.md): 실제 얻은 장비·두 조작·조건당 10시드, 변경 전후 360판씩 비교했다. 자연 조작 봇이 실제 사람을 대표한다고 가정하지 않는다. 회피가 서툰 조건의 점검으로 사용한다.

- 냉각 자연 19→25/40, 회피 40→40/40.
- 공장 자연 16→25/40, 회피 33→34/40.
- 궤도 자연 22→28/40, 회피 34→35/40.
- 일반 60은 자연 1→7/10, 회피 7→8/10. 자연 표본의 무료·구매 경로 장비는 모두 상한이며 [10시드의 공격력·체력·대원 레벨·장착 장비가 일치](reports/curve039-cap-match.json)했다. 현금 구매가 있어야 가능한 승리로 해석하지 않는다.
- 인접 18·31·36·42·48·54작전 120판의 모든 저장 수치는 변경 전과 동일하다.
- 냉각 자연 조작의 저체력 체류 비율 중앙값은 12.7→13.6%로 줄지 않았다. 공장은 15.4→15.0%다. 승리 증가를 체감 문제 전체의 해결로 과장하지 않는다.
- 냉각 21작전 자연 조작은 7→5/10으로 감소했다. 방패를 더 빨리 파괴하면 이동·공격 대상·성장 선택의 경로도 달라질 수 있어, 지역 합계만으로 개별 작전 개선을 주장하지 않는다. 21·28작전과 냉각 방패 이해도는 사람 확인 항목으로 남긴다.

예비 비교에서 상한 60작전이 7승이 된 뒤 이를 3~5승에 맞추려고 다시 어렵게 하지 않았다. 목표는 특정 봇 승률을 맞추는 것이 아니라 기존 성장으로 일반 캠페인을 마칠 여지를 주는 것이다. 새로운 28일 경제 경로·장기 구매 수요·사람의 승률을 재측정한 자료는 아니다. 0.38의 보급 시간 가치 8~10분을 0.39 상품 보장 문구로 사용하지 않는다.

## 실패 시간대에 맞춘 무료 연습

0.38의 15·27작전 기본 연습은 소환 진행도 약 94~154초에 해당했다. 자연 조작의 실제 사망은 15작전 178~231초, 27작전 176~220초로 더 늦었다. 기본 패턴 연습만으로 후반 밀집을 연습하기 어려운 차이가 확인됐다.

새 **실패 구간 연습**은 해당 작전의 서버 검증된 패배 기록에서 시간·스킬 레벨·살아 있던 적 수를 읽는다. 시작 시간은 `패배 시점−30초`, 최대치는 `작전 길이−60초`로 제한한다. 당시 적 수는 12~240 범위로 시작하고, 이후 소환 간격·묶음 수·일반 적 체력은 해당 시간대의 진행도를 사용한다. 처음 3초는 준비 시간을 준다.

당시 스킬을 복원하고 현재 장비로 연습한다. 적의 위치·역할별 정확한 구성·필드 개조·로봇 상태·지형 주기를 통째로 복원하는 사망 장면 재생은 아니다. 연습 선택 화면에도 배치가 달라진다고 안내한다. 기본 연습과 실패 구간 연습을 따로 선택할 수 있고, 새 실패 결과 화면에서는 실패 구간으로 바로 진입한다.

전투 보고서에 작전 번호와 적 수를 저장한다. 작전 번호가 없는 이전 버전 기록은 임의로 추정하지 않고 기본 연습만 제공한다. 새 버전에서 해당 생존 작전에 실패하면 집중 연습이 열린다. 다른 작전의 실패나 중도 포기, 연습 결과로는 열리지 않는다.

두 연습 모두 무료·무보상이다. 재화·현장 보급·일일 진행·작전 완료·로봇 전시 권리를 만들 수 없고, 광고 부활·지원도 허용하지 않는다. 서버가 같은 기록과 입력으로 결과를 재생한다.

## 성능 비교 방법

기존 0.37/0.38 측정은 벽시계 60초 동안 처리한 전투 시간이 달랐다. 느린 프레임에서는 한 번에 수행하는 틱 수와 적 보충 시점까지 바뀌어 부하가 동일하지 않았다. 0.39에서는 비교 전용 QA 측정기를 두 원본 버전에 동일하게 붙였다.

`BuildAndroidPerformanceQA`는 새 QA 프로필·같은 장비·같은 시드·같은 이동·간결 효과로 55작전을 측정한다. 매 프레임 고정 틱 1회, 각 구간 300틱 예열 후 1,800틱을 측정한다. 일반/밀집 구간을 각각 3회 실행한다. 전투 계산과 장면 갱신의 CPU 시간, 실제 프레임 간격, GC 횟수와 검사용 전투 해시를 기록한다. 시간 누적 방식의 실제 게임 FPS와 구분해야 한다.

전투 해시·처치·측정 틱 수가 일치하는지 먼저 확인한다. 해시는 진단용 32비트 값이며 보안 서명이나 전체 상태의 암호학적 증명이 아니다. VFX의 무작위 위치와 기기의 OS/GPU 스케줄링까지 고정한 실험은 아니다. 두 버전 모두 같은 M1 host 에뮬레이터에서 실행하며 실물 폰 성능을 추정하지 않는다.

[12개 구간 비교 결과](reports/performance039/README.md): 밀집 처리량 중앙값 54.6→57.2, 일반 52.7→51.6 프레임/초였다. 같은 0.38 밀집 반복에서도 49.5~58.1로 흔들렸다. 기존 단발 측정의 저하가 일관된 코드 회귀라는 증거는 얻지 못했고, 최적화 완료나 두 버전의 동등성을 주장하지 않는다. p99 지연과 실물 폰 검증은 남는다.

## Android와 최종 검사

[0.39 Android 실행 자료](reports/android039-runtime/README.md): 화면·구매/강화·재출격·무료 연습·지역 부하 검사 오류 0건, 화면 74개, 실제 입력의 IL2CPP→.NET 재생 18/18 일치. 실패 구간 연습 1개와 기본 연습 2개 모두 60초 완료·성장 보상 누수 없음. 코어 133개·Unity 173개·서버 411개 검사 통과. QA와 수동 체험 APK의 ARM64·API26~36·서명·16KB 정렬도 통과했다.

다만 최신 0.39의 궤도 밀집은 평균 34.7 FPS·p99 250ms였다. 실행 오류 0을 성능 합격으로 취급하지 않는다. 고정 부하 비교와 실제 시간 누적 검사는 서로 다른 조건이며, 최신 지연의 원인을 코드 회귀 또는 호스트 환경으로 확정하지 않았다. 성능 최적화는 미해결이며 실물 폰 확인도 필요하다.

## 남은 사람 확인

실물 폰·사람 테스트는 아직 미실시다. 냉각 방패를 보고 측면을 선택하는지, 접촉 후 이탈 여유가 충분한지, 실패 구간 연습이 실제 재도전에 도움이 되는지 확인해야 한다. 강화 상한을 늘리기 전에 기존 상한의 최종 작전 성취감부터 직접 확인하는 것이 우선이다.
