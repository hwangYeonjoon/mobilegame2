# 실제 보상으로 도달하는 작전별 장비

0.31.0 / Android code 34 / 전투 규칙 22. 이번 변경은 오프라인 측정 도구이며 게임 규칙·상점·보상·배포 버전을 바꾸지 않는다. 평균 이용자를 추정하기 전에, 실제 규칙으로 가능한 성장 경로를 분리해 측정한다.

## 이번 측정 결과

강화 3종 × 수령 3종 × 조작 3종 × 시드 5개 = **135개 진행 경로, 실제 정산한 전투 2,295판**이다. 각 경로는 신규 계정에서 시작한다. 한 경로의 최대 모의 경과 시간은 약 108분이어서 이번 실행에서는 서비스 날짜가 바뀌지 않았다. 사람 135명이 참여했다는 뜻이 아니며 셀당 시드 5개로 이용자 승률을 추정하지 않는다.

**분산 강화 + 작전 보상만**인 조건을 아래에 발췌했다. 광고·출석·일일 임무 수령이 없는 기준이다. 진입 공격력/체력은 도달한 경로들의 각각 중앙값이며, 통과는 최초 도전 포함 최대 4회 안에 승리한 경로 수다.

12작전의 분산 강화·회피 경로는 진입 시 무기 Lv.7, 방어구/모듈/대원 Lv.6이 중앙값이다. 첫 클리어 보상으로 얻은 등급과 강화 이전까지 실제 반영된 공격력 184·체력 1,538이며, 이전 고정 Lv.5/초기 등급 프로필과 구분해야 한다. 이 표본에서는 보상만으로 재도전 후 통과 가능한 경로가 있지만, 자연 조작에서는 10~13작전에 여전히 진행 중단이 있다. 이를 모든 사람이 감당할 정상 성장 요구라고 확정할 수 없다.

소극적 강화·회피 조건의 12작전 진입 중앙값은 공격력 148·체력 1,302, 남은 골드 23,250·부품 168이다. 강화하지 않아 약한 상태와 재화가 없어 강화할 수 없는 상태를 구별해야 한다. 분산 강화·회피에서는 같은 작전 잔액 중앙값이 골드 850·부품 22이고 다음 우선 강화의 부족분 중앙값은 골드 950·부품 0이다. 이것도 특정 행동 가정의 결과이며 실제 유저의 부족 재화를 뜻하지 않는다.

추가 수령이 개별 시드의 승리를 보장하지 않았다. 전투 경로, 무기 종류, 스킬·회복 선택 시점이 함께 달라지고 각 조건의 장비도 진행 결과에 의존한다. 따라서 이 자료만으로 광고 필요성·구매 필요성·피해량의 인과 효과를 결론 내리지 않는다. 동일한 회피 대조 쌍도 나중 작전에서는 앞선 승패 때문에 진입 장비가 달라질 수 있다.

**남은 판단:** 실제 참가자가 강화할 재화를 쌓아 두는지, 강화한 뒤에도 같은 보스 공격에 반복 사망하는지 관찰해야 한다. 이번에는 난이도나 경제 수치를 추가 조정하지 않았다.

검증: 성장 모델 자가 검사 **15개**, 집계기의 누락·중복·원장·미도달 검사 **9개**, 기존 게임 코어 검사 **111/111** 통과. 초기 전투 1판은 입력 기록을 서버 재현 검증기로 다시 실행해 승패·처치·체력을 대조했다. 압축 원본에서도 전체 135개 경로의 원장과 정산·진행 순서를 다시 검사했다. 이번 변경은 도구/문서만이므로 새 Android 빌드나 실물 기기 검증을 수행한 것으로 기록하지 않는다.

## 계산 방식

신규 계정의 골드 1,800·부품 30, 기본 장비·대원으로 시작한다. 실제 `Combat` 결과를 `Economy.FinishCampaign`으로 정산한다. 기본 작전 보상, 현장 임무 추가 보상, 첫 클리어 장비·보석, 실패 보상 모두 현재 게임 규칙을 사용한다. 현장 임무 보상은 영수증에 이미 포함되므로 다시 더하지 않는다.

다음 작전은 실제로 이전 작전을 이겼을 때만 열린다. 작전당 최초 도전 포함 최대 4회이며, 실패한 작전의 보상으로 강화하고 다시 도전할 수 있다. 네 번 실패하면 해당 경로는 중단하고 이후 작전 장비는 **미도달**로 둔다. 이전 작전을 반복 파밍하거나 다음 작전을 강제로 열지 않는다.

강화 비용은 계정 복제본에서 실제 강화 명령으로 조회한다. 조회용 재화는 측정 계정에 들어가지 않는다. 강화·장착·강화 이전은 원본 경제 명령으로 실행하고, 모든 재화 변동을 원장으로 남겨 초기 잔액부터 최종 잔액까지 맞춘다. 같은 등급 장비는 현재 종류를 유지하며, 더 높은 등급의 보상 장비를 얻으면 정비소 방문 때 무료 강화 이전 후 장착한다. 무기 종류에 따른 공격 방식 변화도 실제 전투에 반영된다.

### 강화 행동 가정

| 시나리오 | 정비 시점 | 강화 선택 |
| --- | --- | --- |
| `passive` | 완료한 판이 3의 배수일 때만 | 한 번 방문에 최대 1회 강화 |
| `balanced` | 매 출격 전 | 무기·방어구·대원·모듈 중 현재 레벨이 가장 낮은, 살 수 있는 대상부터 |
| `attack_first` | 매 출격 전 | 레벨/가중치가 낮은 순서. 무기 2, 대원 1, 방어구·모듈 0.5 |

분산/공격 우선은 살 수 있는 강화가 없어질 때까지 사용한다. 소극적 강화는 첫 출격 전에 강화하지 않는다. 이것은 **세 가지 행동 가정**이며 사람의 강화 습관을 측정한 결과가 아니다. 도달한 사람만 남는 편향 때문에 작전별 장비 중앙값은 모든 신규 이용자의 평균이 될 수 없다.

### 수령 가정

| 시나리오 | 포함 |
| --- | --- |
| `campaign_only` | 작전·현장 임무·최초 클리어·실패 보상 |
| `daily_claims` | 위 보상 + 수령 가능한 출석·일일 임무 |
| `daily_plus_rewarded` | 위 보상 + 광고 시청에 성공했다고 가정한 부품·결과 추가 보상 |

광고는 실제 SDK를 호출하지 않으며, 서버도 자격 검사에 사용하는 경제 명령의 일일 한도를 따른다. 부품 하루 2회, 결과 추가 골드 하루 3회 및 결과별 중복 제한을 지킨다. 광고가 항상 채워지거나 이용자가 반드시 시청한다고 가정해 일반 결과로 합치지 않는다. 신규 안내 수령 보상, 판매·상점·보석 소비·과금·길드 지원·부활은 제외한다.

시각은 2026-11-09 정오(KST)에서 시작하며 판 사이 실제 전투 시간+30초만큼 전진한다. 출석을 늘리려고 하루를 건너뛰거나 서비스 날짜를 초기화하지 않는다. 실제 사람의 휴식·메뉴 고민 시간은 추정하지 않는다.

### 전투 조작 가정

기존 측정기의 `natural_legacy`, `controlled_ignore`, `controlled_avoid`를 그대로 재사용한다. 마지막 두 방식은 회피 판단만 다르고 스킬 우선순위·보스 추적·버튼 조건이 같다. 자연 조작은 별도 관찰용 봇이므로 회피 여부만 다른 대조군으로 해석하지 않는다. 로봇 목표는 모든 경로에서 설계 5로 고정한다.

같은 시드·작전·시도 번호는 같은 전투 난수 시드를 사용하지만, 앞선 승패와 강화가 달라지면 전체 전투 경로는 달라진다. 이번 시드 공식과 장비가 이전 고정 장비 측정과 다르므로 이전 승률과 짝지어진 수정 전후 비교도 아니다. 추가 보상을 받는 경로가 개별 시드에서 항상 더 잘 이겨야 한다는 뜻은 아니다. 봇의 스킬 선택과 조립 숙련도는 초보 이용자보다 높을 수 있다.

## 재현

저장소 루트에서 실행한다. 원본 결과는 무시 대상인 `TestResults/`에 저장한다. 이번 실행의 전체 계정 원장과 전투 결과는 [압축 원본](reports/growth031-evidence.json.gz), 조건별 전체 표는 [집계 보고서](reports/growth031-summary.md)에 보존했다. 집계 도구는 `.json.gz`도 직접 읽으므로 다른 컴퓨터에서도 전투를 다시 돌리지 않고 원장 검사·표 재생성이 가능하다. 보고서의 SHA-256은 압축을 푼 원본 기준이다.

```sh
dotnet run --project Tools/CoreChecks/CoreChecks.csproj -- --growth-audit-checks
dotnet run --project Tools/CoreChecks/CoreChecks.csproj -- --growth-audit TestResults/growth031-final.json 5 13 4
python3 Tools/summarize_growth_audit.py TestResults/growth031-final.json --json TestResults/growth031-summary.json --markdown docs/reports/growth031-summary.md
python3 Tools/test_growth_report.py
```

숫자 인자는 시드 수·최종 작전·작전별 최대 시도 수다. 최대 시도 4는 첫 도전+재도전 3회를 뜻한다. 1~13작전을 한 계정에서 순서대로 진행하며 10~12작전 뒤의 13작전도 함께 본다. 집계기는 누락/중복 시드, 원장 불일치, 미래 보상 사용, 중복 정산, 미완료 경로를 거절한다. 미도달을 0레벨·0승률로 채우지 않는다.

## 사람 테스트 연결

[기존 관찰표](06-art-combat-and-operations.md#실제-사람-5명--30분-관찰표)를 그대로 사용한다. `Builds/Android/ScrapGuard-playtest.apk`는 수동 조작 체험본이고 `ScrapGuard-qa.apk`는 자동 전투용이다. 신규 QA 데이터에서 시작한 3~5명이 각각 30분 플레이하며 로봇 발견, 2작전 보스 사망 원인, 한 문장 설명과 실제 재출격 행동을 관찰한다.

출격 직전 장비·등급·강화 레벨·대원 레벨·공격력/체력·재화·실제 강화 행동만 추가 기록한다. 체험본은 오프라인이며 광고를 받을 수 없으므로 광고 시나리오와 직접 비교하지 않는다. 실제 참가자·녹화·관찰 결과는 아직 제공되지 않았으며 **사람 테스트와 실물 폰 테스트는 미실시**다. 도구 결과를 참여자 결과로 바꾸어 기록하지 않는다.
