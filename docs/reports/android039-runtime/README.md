# Android 0.39 실행 기록

0.39.0 / build 42 / 전투 규칙 29. 전용 `ScrapGuard_QA_API35`, `emulator-5556`, Apple M1 host OpenGL ES, 540×960. 실물 폰·사람 테스트와 구분한다. 운영 서버와 Play 트랙에는 배포하지 않았다.

## 확인 범위

`ProjectBuilder.BuildAndroidRegionalQA`로 생성한 `.qa` APK를 설치했다. 이전 `RegionalRuntime` 폴더는 다른 이름으로 보존하고 새 결과 폴더에서 시작했다. 자동 QA 뒤에는 `BuildAndroidPlaytest`의 수동 체험 APK로 교체한다.

- 기존 구매 확인 → 보급 구매·즉시 강화 → 강화된 능력치로 재출격을 포함한다. 오프라인 테스트 보석이며 실제 Google 결제·운영 서버 네트워크 재시도 검사는 아니다.
- 실패 화면은 15작전 진행 시간을 190초, 체력을 1로 놓고 일반 적 독성 공격을 주입한 UI 전용 표본이다. 표시되는 1 피해와 실패 보상은 밸런스 근거가 아니다.
- 실패 화면의 실제 버튼으로 실패 구간 연습에 진입한다. 이 표본의 연습 시작 진행도는 약 160초다. 이외 27·57작전은 기존 기본 연습으로 확인한다.
- 연습이 시작된 뒤에는 체력·적 주입 없이 전투 입력을 기록한다. 당시 QA 장비와 UI 표본 스킬을 사용하므로 신규 이용자의 승률로 해석하지 않는다. 연습 종료 후 골드·부품·보석·총 작전 수·현장 보급 시간이 늘지 않는지 확인한다.
- 냉각(19), 용광로(37), 궤도(55)의 일반/밀집 부하를 각 60초 실제 Android 장면에서 실행한다. 체력 보정과 적 주입이 있는 렌더링 부하 표본으로, 승률 자료가 아니다.

`frames-*.json`은 실제 시간 누적 방식의 프레임 간격이다. 버전 간 동일 부하 비교는 별도 [performance039](../performance039/README.md)를 사용한다. 여기서는 실행 여부와 지연을 기록하며, 실물 중저가 폰 FPS·발열·터치 품질로 일반화하지 않는다.

`apk.json`과 `playtest-apk.json`의 `device_execution: not tested`는 파일 검사 도구의 범위다. 실행 결과는 아래 별도로 기록한다. `.qa` 앱은 실서비스 앱과 패키지가 다르다.

## 재현

```sh
python3 Tools/verify_runtime_replays.py docs/reports/android039-runtime --output TestResults/android039-reproduced.json
```

현재 규칙의 `Tools/CoreChecks`를 먼저 빌드해야 한다. 원본 재생 자료는 gzip으로 보존한다. 자동 QA APK를 사람 체험용으로 전달하지 않는다.

## 완료 결과

Android 화면·구매/강화·재출격·연습·부하 검사 오류 **0건**. 화면 캡처 74개 중 주요 화면을 보존했다. 세 연습 모두 60초를 마쳤고 성장 보상 누수가 없었다.

Android IL2CPP 입력 **18/18**개를 .NET으로 재생해 처치·합체 횟수·남은 체력이 일치했다. 압축 보존본도 검사한 원본과 바이트 단위로 일치한다. [재생 결과](replays.json), [검사 수와 한계](checks.json). 코어 133개·Unity 173개·서버 411개 검사를 통과했다.

[연습 선택](46b-failure-options.png), [실패 화면 버튼](45-survival-loss.png), [실패 구간 진입](47-survival-start-14.png), [연습 결과](48-survival-result-14.png), [궤도 밀집](runtime-55-crowded.png)을 확인했다. 연습 선택과 버튼에 잘림·겹침은 없었다.

**성능은 미해결이다.** 0.39 궤도 밀집에서 평균 34.7 FPS, p99 250ms가 기록됐다. 전체 실행 오류가 0이라는 것과 성능 합격은 다르다. 별도 고정 부하의 0.37/0.38 비교에서는 일관된 코드 회귀를 확인하지 못했지만, 이 최신 결과를 그 이유로 무시하지 않는다. 두 측정은 부하 방식이 다르며 0.39 지연의 근본 원인은 확정하지 않았다. 후속 원인 분석과 실물 폰 검증이 필요하다.

[환경 상태](device-status/status.json)는 앱 실행 중 수집한 `emulator_only`다. Unity 빌드·대규모 .NET 측정이 없는 상태에서 6개 부하 구간을 실행했다. 수동 체험 APK는 자동 QA 종료 후 설치했다.

[수동 체험판 시작 화면](manual-start.png)을 확인했고 시작 화면에 남겨 뒀다. APK는 `Builds/Android/ScrapGuard-playtest.apk`이며 0.39.0/code42의 별도 QA 패키지다. 오프라인 체험용으로 운영 계정·Google 실결제를 연결하지 않는다.
