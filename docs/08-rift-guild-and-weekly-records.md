# 0.4 코어 균열·길드 지원·주간 기록

## 실제 추가된 플레이 흐름

일반 구역 5개와 대원 3종은 유지하고, 5구역 클리어 후 도전하는 특수 던전 **코어 균열**을 추가했다. 출격 화면 하단의 ‘특수 던전 · 코어 균열’과 ‘길드 · 지원 대원’에서 들어간다. 길드는 서버 계정이 필요하다. 코어 균열은 로컬에서도 플레이할 수 있으나 서버 순위에는 올리지 않는다.

정식 도전은 90초 동안 중앙 코어에 준 피해량을 점수로 기록한다. 주변 적은 이동과 사격을 방해하며 보스의 범위 공격을 피해야 한다. 사망이나 중도 종료도 30초 이상 진행했다면 점수를 저장한다. 스킬 선택 중에는 전투 시간이 멈춘다. 본인의 캐릭터·장비·스킬·필살기를 사용하므로 성장의 성과를 겨루는 모드다. 같은 주간에는 같은 초기 난수 시드를 발급한다. 조건이 고정된 별도 실력전은 아직 없다.

5구역 이전에도 ‘보상 없는 연습’으로 같은 전투를 체험할 수 있다. 연습 결과는 주간 기록, 재화, 파편, 일일 임무, 업적에 반영되지 않는다. 길드 지원은 일반 구역에서만 사용할 수 있다.

## 전용 보상

주간은 **한국 시간 월요일 오전 5시**에 바뀐다. 전투 시작 시점의 주간에 기록을 귀속한다. 주간이 바뀐 뒤 결과를 제출해도 이전 주간으로 처리한다. 이미 달성한 미수령 보상은 ‘지난 주 보상 보기’에서 나중에 받을 수 있다. 최고 기록을 높이기 위한 재도전은 횟수 제한이 없고, 각 보상 단계는 주간마다 한 번만 지급한다.

| 달성 조건 | 골드 | 부품 | 코어 파편 | 보석 |
| --- | ---: | ---: | ---: | ---: |
| 30초 이상 정식 참여 | 1,000 | 10 | 1 | 0 |
| 코어 피해 5,000점 | 1,000 | 20 | 3 | 0 |
| 코어 피해 15,000점 | 1,500 | 30 | 5 | 0 |
| 코어 피해 30,000점 | 2,000 | 40 | 8 | 50 |
| 주간 모두 달성 | 5,500 | 100 | 17 | 50 |

**코어 파편은 이 던전의 주간 달성 보상으로만 얻는다.** 주간 종료 후에도 보유 수량은 유지된다. Google 결제·보석 구매·일반 장비 판매 경로는 없다. 교환소의 확정 상품은 다음 두 개다.

- 파편 12개: 전용 칭호 ‘균열의 개척자’.
- 파편 20개: 보라색 궤도와 코어 장식의 전시 프레임 ‘코어 궤도’.

교환 전에 수량과 구성을 확인한다. 이미 가진 상품은 다시 차감하지 않으며 공격력·체력을 바꾸지 않는다. 전시실 → 내 프로필 꾸미기에서 적용한다. 독립된 던전 전용 무기·방어구·새 캐릭터는 아직 추가하지 않았다.

## 기록판과 트로피 전시

서버 계정의 정식 도전은 이동·스킬·필살기 입력을 서버에서 재현한 뒤 기록한다. 클라이언트가 보낸 점수/처치/시간을 그대로 사용하지 않는다. 공개 동의한 계정의 이번 주 최고 기록 상위 50명을 표시하고, 자신의 순위는 50위 밖이어도 계산한다. 순서는 점수 내림차순, 같은 점수에서는 먼저 달성한 시각, 마지막으로 공개 ID 순이다. 낮거나 같은 점수로 다시 제출해도 최초 달성 시각을 갱신하지 않는다.

비공개·테스트 계정은 기록판에서 제외하고 차단은 양방향으로 적용한다. 차단한 계정이 빠진 상태에서 순위를 표시하므로 이용자별로 보이는 순위가 다를 수 있다. 프로필을 공개하지 않아도 본인의 주간 보상을 받을 수 있다. 순위에 따른 추가 재화 보상과 자동 시즌 보상은 없다.

기록판에서 전시 프로필로 이동하고 ‘트로피 전시대’를 열 수 있다. 첫 구역 정복, 1,000처치, 코어 도전 달성 트로피 3칸을 보여준다. 코어 트로피는 참여 → 탐색자 → 사냥꾼 → 정복자로 발전하며 주간이 지나도 유지된다. 캐릭터·도색과 역대 코어 최고 기록도 함께 표시한다. 직접 가구를 배치하는 방, 방문 횟수 집계, 방문 알림, 채팅은 아직 없다.

## 길드의 현재 혜택

서버에서 길드를 무료로 만들고 16자리 초대 코드로 가입한다. 정원은 20명이며 계정당 길드 하나다. 길드원에게 닉네임이 표시되고 지원 등록은 별도 선택이다. 미보유 대원은 등록할 수 없다. 지원 대원의 원래 소유권·레벨은 유지되며 빌리는 계정에 캐릭터가 해금되지는 않는다.

| 등록 대원 | 호출 효과 |
| --- | --- |
| 루크 | 최대 체력 25% 즉시 수리 + 8초 사격 지원 |
| 레이 | 8초간 빠른 관통 사격 지원 |
| 볼트 | 최대 체력 40% 보호막 최대 8초 + 8초 사격 지원 |

공통으로 전투 시작 8초 후 버튼 또는 PC Q로 한 번 호출할 수 있다. 자신의 필살기와 별도다. 등록한 대원 레벨과 장착 무기의 화력을 출격 시점에 확정하며 지원 화력은 최대 350으로 제한한다. 지원 대원의 방어구/모듈 특수 효과 전체를 복제하지는 않는다.

빌리는 이용자 기준 **하루 지원 출격 3회**, 한국 시간 오전 5시에 초기화한다. 횟수는 호출 시점이 아닌 **지원 대원과 출격할 때** 차감된다. 출격 전 확인 화면에 이 조건을 표시하며 중단·앱 종료 시 반환하지 않는다. 지원 없이 출격하면 차감하지 않는다. 길드를 바꿔도 계정의 일일 사용량은 유지한다.

자기 자신, 다른 길드, 지원 등록을 해제한 대원, 차단 관계의 대원은 새로 빌릴 수 없다. 이미 발급한 전투 티켓은 대원이 등록을 바꾸거나 길드를 떠나도 동일한 결과로 정산할 수 있도록 당시 능력치가 유지된다. 길드장 탈퇴/계정 삭제 시 다른 길드원에게 자동 위임하고, 마지막 회원이 떠나면 해산한다.

이번 버전의 길드 스킬은 대원에 연결된 지원 호출이다. 길드 경험치·공용 스킬 트리·길드 공동 보스·기부·주간 기여 보상·길드 채팅은 아직 없다. 다음 확장에서는 ‘길드 공동 보스를 통한 길드 경험치 → 지원 계열 선택’으로 연결할 수 있다. 수치 상향을 넣기 전에 현재 지원이 구역 난이도를 얼마나 낮추는지 실기기 플레이로 확인해야 한다.

## 저장/API와 호환성

전투 규칙 버전은 4다. 새 전투 모드와 지원 이벤트를 모르는 이전 앱은 전투 시작을 거절한다. 기존 미완료 전투는 계정 화면에서 취소하고 새 전투를 시작한다. 기존 재화·출석·캐릭터·장비 저장 버전은 유지한다. 주간 진행·파편과 신규 외형 소유권을 추가하고, 기존 프로필에서 누락된 필드는 기본값으로 보완한다.

SQLite에 `weekly_records`, `guilds`, `guild_members`, `accounts.run_support`를 추가한다. 기존 `run_rules`도 마이그레이션한다. 재화 지급·파편 교환·길드 생성/가입·전투 티켓은 기존 요청 원장과 트랜잭션으로 중복 처리를 막는다. 파편 변동은 `ledger.currency=core_shards`에 남는다. 계정 삭제 시 해당 기록과 길드 회원 정보도 정리한다.

추가 API는 인증된 `GET /v1/weekly`, `GET /v1/guild`와 기존 명령 API의 `guild_create`, `guild_join`, `guild_support`, `guild_leave`, `weekly_claim`, `core_exchange`다. `battle_start`에 `mode`와 선택적 `supportId`를 받되 주간·능력치·일일 한도는 서버가 확정한다. 지원 없는 티켓은 `hasSupport=false`로 명시한다. Unity JsonUtility가 JSON null 중첩 객체를 빈 객체로 만드는 경우에도 이를 실제 지원 대원으로 사용하지 않는다.

아직 서버 부하 시험, 랭킹 부정 자동화 대응, 신고 운영 화면, 실결제·광고 연결은 완료하지 않았다. 공개 서버도 배포하지 않았으며 이번 검증은 별도 로컬 Docker 스택에서 수행한다.

## 로컬에서 두 계정으로 길드 체험하기

검증용 Docker 서버는 이 Mac의 `http://127.0.0.1:5190`에만 열려 있다. 신규 계정의 초대 코드는 `local-integration-test-invite-03`이다. 운영용 코드가 아니며 공인 서버로 노출하지 않는다. 앱의 설정 → 계정·서버 연결에서 주소와 초대 코드를 입력하고 복구 코드를 비워 두면 새 계정이 만들어진다. 두 번째 기기나 별도 앱 프로필로 다른 계정을 만든 뒤 길드 초대 코드를 공유한다. Android USB 연결은 `adb reverse tcp:5190 tcp:5190` 후 같은 주소를 사용한다.

서버가 정지되어 있으면 프로젝트 루트에서 `docker compose -f Server/Deploy/compose.local.yaml up -d`로 시작한다. 이 테스트 서버와 데이터는 공개 운영 서버와 분리되어 있다.
