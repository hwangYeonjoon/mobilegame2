## 2026-11-06 구매 후 출격·전투 가독성·대원 동작 — 로컬 후속 변경

구매 완료 화면과 보유 의상실에 **장착하고 이 모습으로 출격**을 추가했다. 기존 `outfit_equip` 성공 → `hero_select` 성공 확인 후 현재 선택 작전으로 출격한다. 의상을 이미 장착했다면 중복 장착 요청을 보내지 않으며, 미보유 의상이나 실패한 명령은 출격시키지 않는다. 길드 지원을 선택한 온라인 계정은 기존 출격 확인 절차를 사용한다. 구매만으로 전투가 시작되지 않으며, 장착·전시·출격 준비 동작도 계속 제공한다. 외형 전용 상품 가격, 능력치, 지급 및 결제 규칙은 변경하지 않았다.

전투 대원 표시 배율을 0.88에서 1.0으로 확대했다. 플레이어와 지원 대원을 아군 효과보다 위에, 위험 경계를 대원보다 위에 그린다. 의상별 실루엣·전용 탄환을 간결 모드에서도 유지하며 상단에 현재 의상을 표시한다. 피팅룸 전투 크기도 같은 배율을 사용한다.

설정과 전투 일시정지에서 자동/풍부하게/간결하게를 고를 수 있다. 자동은 적 100마리 또는 탄환 160개 이상, 혹은 42fps 미만 프레임이 누적 1.5초를 넘으면 연출을 줄인다. 성능 원인의 축소는 52fps 이상이 5초 유지되면 해제한다. 메뉴·일시정지 시간은 측정하지 않는다. 간결 모드는 입자 최대 160→48, 신규 부유 효과 최대 36→12, 효과 투명도 조정, 기본 탄환 꼬리와 화면 흔들림 축소를 적용한다. 적·탄환 본체·위험 경계·피해 판정과 리플레이는 유지한다. 반복 피해 문구·원형 효과·전격 선은 종류별 오브젝트 풀로 재사용하고, 체력/시간/처치/스킬 HUD는 값이 바뀔 때 갱신한다.

대원 5명에 기본/앰버/서리 각각 걷기 4프레임·사격 1프레임·피격 1프레임을 연결했다. 각 시트는 6열×3행이며 총 90프레임이다. 대기는 기존 원화를 사용하고, 지역 도색은 기본 프레임에 기존 색을 적용한다. 의상 10종은 기존 전용 자세를 유지하면서 호흡·걸음·반동을 적용한다. 전투 동작은 시뮬레이션 시계에 따라 멈추고, 체험 화면은 별도 미리보기 시계를 사용한다. 지원 대원도 공개 허용된 외형으로 사격 동작을 표시한다. 뼈대 애니메이션이 아닌 2D 프레임 방식이다.

새 아트: `Assets/Resources/Art/GuardianMotion-{Luke,Ray,Volt,Spark,Iris}-v1.png`. 생성 및 배경 정리 프롬프트는 같은 이름의 `ArtSource/*.prompt.txt`에 보존했다. imagegen으로 제작했으며 생성 원본은 삭제하지 않았다. 새 시트 원본 PNG 합계 약 9.6MB이며 Android 텍스처 메모리와 압축 품질 확인은 남아 있다.

정비소의 **성장 · 수집 목표**에서 다음 작전, 미모집 대원, 지역 도색 설계도, 목표 의상을 함께 확인한다. 진행률은 실제 저장 상태와 보유 재화를 사용한다. 목표 화면을 보는 것으로 보상·구매·재화 변경은 발생하지 않으며 각 획득 화면으로 이동한다. 대원 목록의 **동작 체험**에서는 미보유 대원도 기본/앰버/서리와 대기/걷기/사격/피격을 확인할 수 있다.

Play 버전·운영 서버·기존 비공개 테스트 배포는 변경하지 않았다. 실기기 터치, 저사양 Android 장시간 성능/발열, 신규 이미지 메모리, 실제 이용자의 구매 만족도는 별도 검증 대상이다.

생성 도구는 imagegen 내장 도구. 원본은 기존 생성 디렉터리에 보존하며 파일명은 각각 `exec-6dc37399-14e8-415b-a475-0fb08eaa00ae.png`, `exec-e2cd4a8c-3391-419a-aadf-306c88adabfa.png`, `exec-2702ac76-78bd-4cb0-81e9-64b2c8cf3519.png`이다. 상점 그림은 최초 출력의 흰 배경을 같은 도구로 제거한 결과다. 지급 수량·상품 ID·Google Play 가격 처리와 기존 경제 규칙은 유지한다. 그림 속 보석의 개수는 지급 수량을 뜻하지 않으며 상품 이름에 확정 지급 수량을 표시한다.

메뉴는 안전 영역의 전체 높이를 사용한다. 정비소의 작전명·이전/다음 선택·출격은 고정 하단에 함께 표시해 짧은 화면에서도 작전을 확인하고 출격할 수 있다. 긴 정비소·상점·전시실은 스크롤하고, 장비/상품/의상/스킬은 카드 전체 선택을 지원한다. 장비 상세, 의상 체험, 메뉴 이동 버튼도 확대했다. 전투의 540×960 시뮬레이션 좌표와 리플레이 규칙은 그대로다. 정비소·의상 추천·전시 카드에는 공통 정비대, 조명, 받침대를 추가했다. 전시 카드는 대표 모습·칭호·작전 정복을 우선 표시하고 장비·공격/체력·처치/출석은 별도 상세에서 확인한다. 공개 프로필에도 같은 상세 접근을 제공한다. 스크롤 위치와 무관하게 전체 전시 카드를 복사하여 공유 캡처한다.

의상 목록은 두 열 썸네일, 시리즈·대원·보유·장착 가능 조건을 함께 적용한다. 빈 결과에 초기화 동작을 제공한다. 작은 전투 크기에서는 의상별 장식을 더 적고 굵은 실루엣으로 바꾸며 피팅룸도 동일하게 적용한다. 몬스터 외곽선, 움직임에 따른 플레이어 그림자, 구조물의 드리운 그림자, 맵 가장자리 명암과 최대 12개의 낮은 대비 환경 입자를 보강했다. 환경 효과는 시뮬레이션 시간으로 갱신하며 위험 표식 아래에 남는다.

기본/확장 대원 전체의 새 연속 걷기·피격 스프라이트 제작은 이번 변경에 포함하지 않는다. 기존 자세 전환과 반동·기울기 동작을 유지하고 전투 크기 가독성을 보강한 범위다. Android 실제 터치 편의·장시간 성능·구매 전환 효과는 별도 실기기/사용자 검증 대상이다.

## 이번 구현

캐릭터는 수집하고 싶은 장난감 로봇 방향을 유지한다. 어린이 전용 타깃은 아직 확정하지 않았으며, 청소년·성인 중심의 수집형 게임을 작업 가정으로 사용했다. 상점에서 도색을 크게 보고 모든 대원에게 입혀 볼 수 있다. 미보유 대원 미리보기는 구매나 능력치 변경을 일으키지 않는다. 도색은 기존 확정 가격과 업적 획득 구조를 유지한다.

몬스터는 녹슨 수집 로봇·보라색 고속 로봇·중장갑 정예·폭주 코어 보스 4종에 각각 4프레임 이동 아트를 연결했다. 바닥은 금속 패널과 배관이 있는 정유 공장 아트로 교체했다. 5개 구역은 같은 지형의 색상 변형이며 서로 다른 맵 구조나 장애물 충돌은 아직 없다.

플레이어는 이동 시 상하 움직임·기울기·좌우 방향 전환, 사격 시 반동·총구 섬광, 피격 시 색 변화가 있다. 캐릭터 자체의 뼈대 애니메이션이나 별도 걷기 프레임은 아직 없다. 탄환 코어, 보스 공격 경고 테두리, 보호막, 필살기 파동·광선과 효과음을 추가했다.

## 공개 서버 권장안

첫 비공개 베타는 **서울 리전의 작은 VM 한 대 + Docker Compose + Caddy HTTPS + API + 영속 SQLite**로 시작한다. 초기에는 실시간 멀티플레이 서버가 필요하지 않다. 전투는 기기에서 실행하고 서버는 계정·경제·전시·입력 재현 정산을 담당한다.

AWS Lightsail Linux 공인 IPv4 요금표 기준 2GB/2vCPU는 월 US$12, 4GB/2vCPU는 US$24다. 우선 4GB로 서버 빌드와 운영 여유를 확보하는 안을 권한다. 도메인·백업·초과 전송량·세금은 별도이며 동시접속 수를 보장하는 산정은 아니다. 서버 검증 전투가 CPU를 사용하므로 부하 테스트 후 규모를 정해야 한다. [AWS Lightsail 가격](https://aws.amazon.com/lightsail/pricing/).

유료 출시 또는 서버 여러 대가 필요해지면 PostgreSQL과 관리형 백업/PITR로 옮기고 계정 인증·결제 검증을 먼저 보강한다. 현재 저장소는 프로세스 내부 잠금과 SQLite 파일 하나를 사용하므로 API를 수평 확장하지 않는다. Cloud Run 같은 서비스로 이동할 경우 로컬 SQLite 파일을 그대로 저장소로 사용할 수 없다. [Cloud Run 파일 시스템 수명](https://docs.cloud.google.com/run/docs/container-contract#file_system).

## 배포 준비

`Server/Deploy/compose.yaml`은 공개 운영 준비용 템플릿이다. 이번 작업에서는 외부 VM, DNS, 인증서, 유료 리소스를 만들지 않았다.

1. VM에 Docker Engine/Compose를 준비하고 API 도메인의 A 레코드를 공인 IPv4로 연결한다. 실제 IPv6를 설정하지 않았다면 AAAA 레코드는 넣지 않는다.
2. 방화벽은 80/443을 공개하고 SSH는 운영자 IP로 제한한다. API 8080이나 SQLite는 외부에 공개하지 않는다.
3. 프로젝트를 서버에 복사하고 다음처럼 환경 파일을 준비한다.

```sh
cd Server/Deploy
cp .env.example .env
chmod 600 .env
```

`.env`의 `GAME_DOMAIN`, `ACME_EMAIL`, `BETA_INVITE_CODE`를 실제 값으로 바꾼다. 초대 코드는 16~80자이며 예제의 `replace-` 값으로 서버를 시작하면 실패한다. 생성 예: `openssl rand -hex 24`. 초대 코드와 게스트 개인 복구 코드는 다른 용도다. 신규 가입은 기본 닫힘 상태다.

```sh
docker compose --env-file .env config --quiet
docker compose up -d --build
curl --fail https://YOUR_API_DOMAIN/health
curl --fail https://YOUR_API_DOMAIN/health/ready
```

HTTPS와 백업·복구 확인 후 `.env`의 `REGISTRATION_ENABLED=true`로 바꾸고 `docker compose up -d api`로 재생성한다. 앱의 설정 → 계정·서버 연결에 HTTPS 주소와 초대 코드를 입력한다. 기존 계정 복구는 가입 종료 후에도 가능하다.

API는 비루트 사용자, 읽기 전용 루트 파일 시스템, 제한된 임시 파일 시스템과 capability로 실행한다. Caddy만 외부 포트를 받는다. 신뢰 프록시는 고정 사설 IP `172.31.248.2` 한 개다. 이 대역이 호스트 네트워크와 겹치면 Compose 대역과 `TRUSTED_PROXY_IPS`를 함께 바꾼다. [ASP.NET Core 프록시 설정](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer?view=aspnetcore-10.0), [Caddy 전달 헤더 기본 동작](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#defaults).

IP별 분당 180요청, 신규 등록은 별도로 분당 10요청으로 제한한다. 전투 명령 등 `/v1/commands`에는 동시 처리 제한 2개와 대기열 8개를 둔다. 이는 초기 방어 장치이며 부하 테스트나 DDoS 보호를 대체하지 않는다. 전시 신고는 DB 접수까지 구현되어 있으므로 공개 모집 전에 운영자가 신고를 확인하고 처리하는 절차가 필요하다.

## 백업·복구·점검

배포 디렉터리에서 `sh backup.sh`를 실행하면 실행 중인 DB의 일관된 스냅샷을 만들고 무결성과 외래키를 검증한 뒤 `backups/`로 내보낸다. WAL 파일을 제외한 단순 파일 복사는 사용하지 않는다. SQLite 온라인 백업 중에는 잠시 쓰기가 막힐 수 있어 트래픽이 적을 때 실행한다. [SQLite Backup API](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup).

운영자는 하루 1회 이상 자동 실행, 별도 서버/암호화 오브젝트 스토리지 복사, 보관 기간과 복구 훈련을 설정해야 한다. 이 원격 백업 자동화와 알림은 아직 연결하지 않았다. VM 안의 백업 볼륨만으로는 VM 손실에 대비할 수 없다. 일일 백업만 사용하면 최대 하루 진행 손실 가능성이 있다.

복구는 우선 별도 테스트 DB/볼륨으로 한다. 아래 CLI로 파일을 검증하고, 복사한 백업을 `GAME_DB`로 지정한 별도 API에서 계정·재화·원장을 확인한다.

```sh
docker compose exec -T api dotnet ScrapGuard.Server.dll --verify-backup /backups/SELECTED_BACKUP.db
```

실제 교체 시에는 신규 가입을 닫고 `MAINTENANCE_MODE=true`로 API를 재생성해 쓰기를 막는다. 현재 DB도 추가 백업한다. 그 뒤 API를 완전히 정지하고 새 볼륨에 검증된 백업을 배치한다. 이전 DB의 `-wal`/`-shm` 파일을 새 백업과 섞지 않는다. 새 볼륨을 API 사용자에게 쓰기 가능하게 연결하고 점검 모드로 재기동한다. `/health/ready`와 계정 읽기를 확인한 뒤 점검 모드를 푼다. 이전 볼륨은 복구 확인 전까지 보존한다. 백업 이후 거래는 되돌아갈 수 있으므로 출시 후 결제 원장과 복원 처리를 포함한 별도 절차가 필요하다.

모니터링은 외부 `/health/ready`, 컨테이너 재시작/메모리, 디스크 사용량, 5xx/429, 백업 성공 시각을 대상으로 연결한다. 현재 알림 서비스는 연결하지 않았다. Docker 로그는 파일당 10MB·3개로 제한했다. 배포 이미지는 검증된 태그/다이제스트를 기록해 교체하고 정기 보안 업데이트 때 다시 검증한다.

## 0.21 전투 구조 확장 — 배포 전 개발본

일반 작전은 중앙 임무 배치를 유지하면서 바닥·장애물·지역 지형을 3×3으로 확장했다. 전장의 범위는 x=-540..1080, y=-480..1480이고 플레이어 중심으로 화면이 이동한다. `Campaign.WorldGeometry`를 시뮬레이션과 표시가 함께 사용한다. 기존 42개 작전과 7지역을 재사용하며, 42개의 새로운 수작업 맵을 제작했다는 의미는 아니다. 순위 도전은 기존 제한 전장을 유지한다.

전투 표시 영역은 안전 영역 전체이고 상단 정보와 하단 조작부가 겹쳐 표시된다. 초보 안내는 첫 18초까지만 표시하며 지속 개조 설명은 전투 화면에서 걷어냈다. 실제 획득한 스킬만 하단에 표시한다. 홈은 큰 출격 버튼, 성장 버튼, 활동 메뉴를 중심으로 구성했다.

군집은 일반 출현 2~6마리와 별도 웨이브로 구성한다. 첫 웨이브는 22초에 예고되며 2.4초 뒤 접근한다. 포위에는 약 80도 탈출 구간을 둔다. 작은 적의 체력을 낮춰 처치와 회수를 늘렸으며 정예/보스는 강한 목표로 남는다. 보스는 단일 포격, 시간차 교차 포격, 탈출 틈이 있는 원형 봉쇄를 순환하고 반 체력 이하에서 추가 포격을 사용한다. 기존 지역별 역할 행동도 유지한다.

신규 스킬: 곡사 박격포(목표 주변 폭발), 십자 절단기(네 방향 관통), 지뢰 살포기(지연 무장 후 접근 감지), 회수 엔진(회수량 2배와 레벨별 이동 속도). 리벳 Lv.5 뒤 고밀도 Lv.3을 먼저 달성하면 중장, 장전 Lv.3을 먼저 달성하면 분산 진화가 잠긴다. 이후 반대 스킬을 키워도 바뀌지 않는다. 동일 선택 순간 양쪽 조건을 충족한 외부 fixture에는 중장을 우선한다.

핵심 특징은 `처치 → 고철 회수 → 대형 기계 합체 → 군집 정리`다. 고철은 실제 수집한 경험치에서 산출하는 이번 전투 전용 자원이며 상점 부품/골드를 지급하지 않는다. 첫 합체는 40, 이후 120을 소비하고 12초 작동한다. 현장 자력 개조는 범위, 수리 개조는 회복, 포탑/레일 개조는 관통 사격을 더한다. 위험 경고는 항상 아군 기계와 효과보다 위에 표시한다.

새 합체 외형은 내장 image_gen으로 생성한 `Assets/Resources/Art/SalvageMachine-v1.png`이며 투명 원본을 보존한다. 최종 프롬프트와 제작 방식은 `ArtSource/SalvageMachine-v1.prompt.txt`에 기록했다. 음악 `Assets/Resources/Audio/SalvageDrive.wav`는 `Tools/generate_combat_music.py`로 직접 합성한 약 34초 원본 루프이며 외부 음원 샘플을 사용하지 않는다. 효과음/음악/진동을 각각 설정할 수 있다. Android 진동은 [VibrationEffect](https://developer.android.com/reference/android/os/VibrationEffect)의 짧은 펄스로 피격, 성장, 필살기, 합체에 연결한다.

탄환은 80단위 공간 격자에서 인접 적만 조회하고 ID 순서를 유지해 충돌 순서가 바뀌지 않게 했다. 화면 밖 적/탄환/경험치의 시각 객체는 재사용한다. 이는 성능 개선 구조이며 저사양 Android에서 60fps를 보장한다는 의미는 아니다.

사람 테스트 준비: 실제 터치로 첫 3분 이동·회수·합체를 이해하는지, 포위 틈을 인식하는지, 소리/진동이 피로하지 않은지, 재도전을 원하는지 관찰한다. Android 실기기에서 20분 이상 프레임·발열·메모리·전화/백그라운드 복귀를 확인한다. 사람 검증 결과는 아직 없다. 기록 동의와 내보내기를 거친 데이터만 버전·플랫폼별로 집계하며 재플레이 의향 응답을 실제 재방문율로 표현하지 않는다.

## 0.22 가독성·진화·합체·음향 보완

적 간격 유지는 주변 80단위 셀만 조회하고 한 쌍을 한 번 처리한다. 겹친 적의 이동량을 먼저 모아 동시에 적용하며 프레임당 밀림을 제한한다. 장애물 충돌·전장 경계를 유지하고 전투 난수를 소비하지 않는다. 일반 적 그림은 반경의 3.9배에서 2.7배로 줄였으며 정예·보스는 큰 실루엣을 유지한다. 플레이어는 민트 윤곽, 탄환은 흰 중심, 처치는 밝은 파편으로 구분한다. 탄환 후보는 같은 셀에서 한 번 순서 병합해 재사용한다. 이 구조 개선만으로 저사양 폰의 프레임을 보장하지 않는다.

상단 시간·체력 아래에는 위험 구역 → 포위/군집 → 진화 알림 → 초보 안내 → 목표 안내 순으로 문구 하나를 표시한다. 위험 경고 중에는 연속 처치 문구를 숨긴다. 회수·개조 버튼은 하단 조작부로 옮겼고 긴 화면에서는 상단과 하단 HUD를 안전 영역 끝으로 이동한다. 필살기와 합체는 서로 다른 버튼이다. 설정은 전투 일시정지 화면에서도 접근할 수 있다.

| 진화 | 조건 | 실제 변화 |
| --- | --- | --- |
| 행성 절단륜 | 톱날 5 + 자력 3 | 궤도 확대·큰 민트 톱날·타격 반경 증가 |
| 극저온 폭풍 | 코일 5 + 수리 3 | 넓은 동결 영역과 추가 피해, 보스 동결 제외 |
| 삼각 드론 편대 | 드론 5 + 장전 3 | 실제 사격하는 드론 3기 |
| 융단 포격 | 박격포 5 + 고밀도 3 | 넓게 펼친 3개 포격 영역 |
| 귀환 절단기 | 절단기 5 + 회수 엔진 3 | 회전하는 관통 탄환이 플레이어에게 귀환 |
| 연쇄 지뢰망 | 지뢰 5 + 자력 3 | 무장된 인접 지뢰가 연쇄 폭발, 연결 표시 |

합체는 고철을 모은 뒤 하단 버튼으로 발동한다. 처음 40, 이후 120, 지속 12초 규칙은 유지한다. 자동 발동은 기기 설정에서 선택하며 자동/수동 모두 동일한 `ReplayStep.machine`을 기록하고 서버가 보유 고철·생존·도전 여부·중복 발동을 검증한다. 구매나 광고가 합체 조건에 영향을 주지 않는다. 기계는 적보다 앞, 플레이어와 위험 예고보다 뒤에 표시한다.

바닥은 내장 image_gen으로 생성한 `Assets/Resources/Art/ContinuousFloor-v1.png`를 미러 반복한다. 원화는 수정하지 않았고 원본에 가정한 이음매 정확도에 의존하지 않는다. 프롬프트는 `ArtSource/ContinuousFloor-v1.prompt.txt`다. 지역 시설·위험 지형·충돌은 기존 지역별 배치를 유지한다. 음악은 Alexander Ehlers의 CC0 3곡, 효과음은 Kenney의 CC0 12종이다. 원문 라이선스 링크·다운로드 고정 버전·원본 효과음·음량 조정 내역·해시는 `ArtSource/Audio/`에 보관한다. 음악은 스트리밍, 효과음은 한 번 로드하여 재사용한다.

### 재현과 검증 범위

```sh
dotnet run --project Tools/CoreChecks/CoreChecks.csproj
dotnet run --project Server/Checks/Checks.csproj
unity test . --mode EditMode --output TestResults/readability-verified-editmode.xml --timeout 240
unity run . --timeout 240 -- -buildTarget StandaloneOSX -executeMethod ScrapGuard.Editor.CombatRuntimeAudit.CaptureAndBuildMac
python3 Tools/verify_runtime_replays.py TestResults/RuntimeAuditFinal --output TestResults/readability-editor-replays.json
unity run . --timeout 900 -- -buildTarget Android -executeMethod ScrapGuard.Editor.ProjectBuilder.BuildAndroidAssaultQA

```

macOS 앱에 `-smoke -assaultSmoke`를 넘기면 군집·합체·전체 진화·작은 화면 검사를 수행한다. `-smoke -naturalCombat`은 초기 장비의 자동 조작 3회를 정상 전투 종료까지 기록한다. 모두 별도 `-profilePath`와 `-smokeOutput` 경로를 사용한다. 이 모드는 적·체력·스킬·전투 시간을 주입하지 않으며 전략은 정해진 봇 정책이다. 자연 전투 폴더의 `runtime-replay-natural-*.json`을 서버 시뮬레이션으로 재생한다. `python3 Tools/render_combat_clips.py <자연 전투 폴더>`로 합체 이후 15초를 담은 5fps 무음 영상을 만든다. 보간하거나 가짜 처치를 더하지 않는다. 캡처 부하가 있으므로 이 실행의 화면 속도를 실기기 FPS로 보고하지 않는다.

### 실기기와 첫 3판 관찰

## 0.23 합체 빈도·보스전·난이도 측정

고철 합체는 10초 발동, 종료 뒤 40초 재사용 대기다. 첫 비용 40·이후 120은 유지하고 대기 중 고철을 보관한다. 횟수×지속 시간 추정 대신 `MachineActiveSeconds`로 실제 가동을 누적하며, 직접 타격과 합체 탄환의 유효 피해를 `MachineDamage`로 분리한다. 사망으로 짧게 끝난 판은 가동 비중이 높게 나올 수 있으므로 완료 판과 구분한다.

보스 등장 3초 전 예고하며 등장 시점의 플레이어 주변에 470×600 구역을 만든다. 월드 가장자리에서는 중심을 보정하되 플레이어를 장애물로 이동시키지 않는다. 2초 보호와 첫 패턴 지연을 주며 지역 시설·장판·작전 전격은 보스전 동안 제거한다. 보스와 일반 적은 울타리 안에 머물고 카메라는 전투 구역 중심에 고정한다. 보스전에서는 일반 묶음 출현을 중지하지만 보스 소환 행동은 유지한다. 일반 보스 기본 체력은 7,000에서 20,000으로 조정했다. 고정 순위 도전의 보스·지형 규칙은 별도 유지한다.

일반 작전 진화 조건은 공격 4 + 보조 2다. 선택창의 한 후보는 이미 투자한 공격이나 그 보조 조건으로 제시하며 플레이어가 선택한다. 12레벨 이후 필요 경험치에 레벨당 6을 더해 모든 스킬 완성을 늦춘다. 후반 경험치는 지역에 따라 `1 / (1 + 지역번호 × 0.2)` 비율로 정수 누적하여 줄이고, 일반 작전 회복 드롭은 60처치마다 체력 10%로 조정한다. 받는 피해는 지역마다 10% 증가한다. 순위 도전은 기존 경험치·5+3 진화·회복 드롭 규칙을 유지한다.

### 화면·음원·실기기 기록

보스 이름과 체력바는 같은 패널의 자식으로 묶어 빈 패널과 따로 떠 있는 글자를 없앤다. 필살기는 한 줄 상태 문구로 표시하고 하단 조작 배경을 불투명하게 해 소품이 조이스틱 아래 보이지 않게 한다. 보스전의 아군 범위 투명도를 낮추고, 적 위험 예고를 마지막 레이어로 표시한다. 위험 장판은 남은 초와 임박 표시를 구분한다. 전투 종료 캡처 전에도 최종 프레임을 다시 그려 오래된 처치 수가 남지 않게 한다.

Kenney 공식 Impact/Sci-fi/RPG ZIP을 직접 다운로드했고 12개 효과음이 기존 사본과 바이트 단위로 같음을 확인했다. 원본을 공식 ZIP에서 다시 저장했으며 원문 라이선스와 ZIP/파일 해시는 `ArtSource/Audio/OfficialLicenses` 및 `official-provenance.json`에 보관한다. 음악은 원본을 보존하고 Unity 가져오기 설정만 최적화한다. `TestResults/BuildSize`의 보고서는 상위 자산의 포장 크기도 기록한다. ## 0.24 초반 위협·성장 곡선·피해 원인 분리

이전 0.23의 `hazardDamage`는 바닥 피해가 아니다. 적 포격·폭발·보스 예고까지 포함하고 직접 독성 웅덩이 피해는 빠지는 ‘지연 예고 피해’다. 또한 `bossSeconds` 전체 평균에는 보스에 도달하지 못한 0초가 섞였다. 0.24 집계는 `DamageSource`로 접촉/적 공격/지형/작전/보스를 구분하고 보호막·초과 피해를 제외한 실제 체력 감소를 합산한다. 보스 도달 수, 도달 판 평균, 승리 판 평균과 패턴 횟수를 분리한다. 기존 `DamageCause` 사망 원인·전투 결과 형식은 유지한다.

### 난이도와 성장 규칙

일반 작전은 첫 12초 추격형 적을 소개하고, 25초까지 묶음당 2마리로 시작한다. 포격형과 폭발형은 각각 25초 전 1마리, 이후 3마리까지 두며 초과 후보는 추격형으로 나온다. 일반 적의 지연 공격은 0.8초 발사 간격, 동시 예고 2개(25초 전)/3개, 최소 1.6초 예고를 공유한다. 폭발형은 예고를 만들 수 있을 때만 폭발 준비에 들어간다. 일반 위험 공격 간 0.55초, 보스 공격 간 0.45초 피격 간격으로 한 프레임에 여러 경고가 터져 체력이 사라지는 상황을 막는다. 보스의 예고 개수 자체를 일반 적 예산으로 잘라내지 않는다.

지역 지형의 기본 피해는 35%로 낮추고, 첫 12초 접촉·일반 위험 피해는 25%, 12~20초는 100%까지 단계적으로 올린다. 적 포격 기본 피해는 80%이며 접촉/포격의 작전 배율은 `1 + 작전ID × 0.022`다. 적 체력의 기본 난이도는 `1 + 작전ID × 0.05`로 조정한다. 고정 순위 도전의 피해·성장·출현 규칙에는 이 완화를 적용하지 않는다.

진화는 공격 5 + 대응 보조 3이다. 일반 작전 경험치 비용은 `(8 + 레벨×6 + max(0, 레벨-12)×6) × max(1, 작전시간/180)`이며 정수로 내린다. 획득 경험치 지역 계수는 `1/(1+지역번호×0.2)`를 유지해 후반의 더 많은 처치가 진화를 지나치게 앞당기지 않게 한다. 격레벨마다 이미 투자한 공격/보조를 한 후보로 제시하며 자동 선택하지 않는다. 진화에 시간 제한을 걸거나 특정 시점에 능력치를 주입하지 않는다. 첫 진화 40~60%는 측정 목표이며 모든 빌드의 보장 시점이 아니다.

일반 보스 기본 체력은 50,000에 작전 난이도를 적용하고 공통 패턴 간격은 3.8초다. 플레이어 장비에 맞춰 체력을 자동으로 높이거나 보스가 받는 피해를 일괄 삭감하지 않는다. 더 강한 장비가 보스를 빨리 처치하는 효과를 유지한다.

합체는 지속 10초·종료 후 대기 40초를 유지한다. 추적 속도 200, 플레이어와의 기준 거리 45, 범위 210(범위 개조 255), 0.7초마다 일반 적 피해 4.8배/정예·보스 4배로 조정했다. 발동 순간 230 범위 내 일반 적 포격 예고를 걷어내며 보스·지형은 제외한다. 실제 합체 피해·직접 처치·포격 차단·가동 중 전체 피해/처치와 가동 밖 처치를 따로 기록한다. 가동 시기에는 적 밀도도 다르므로 두 시간대 처치율을 순수한 인과 효과로 해석하지 않는다.

일반 장비의 레벨당 증가 계수는 장비 기본 기여량의 5%에서 12%로 조정했다. 전체 공격/체력이 매 레벨 12% 증가한다는 뜻은 아니다. 첫 레벨·희귀도·강화 비용은 유지하며 인벤토리 비교·강화 완료 화면과 실제 전투는 같은 계산을 쓴다. 고정 도전은 명시적으로 기존 5% 계수로 계산해 공통 장비와 점수 조건을 유지한다.

## 0.25 첫 승리와 지역 진입 난이도 완화

첫 승리 전 1작전(`stage == 0 && !tutorialCompleted`, 일반 작전)에만 입문 보스를 적용한다. 기본 체력은 18,000에 기존 작전/시간 배율을 적용하고, 피해는 기존의 45%, 보스 피격 간격은 0.8초다. 원형 또는 가로 장판 하나를 2.2초 예고하고 공통 패턴 간격은 5초다. 돌진 준비는 1.3초, 속도 145, 재사용 6초로 반응 시간을 준다. 자동 승리·체력 하한·무료 부활은 없으며 첫 승리 뒤 재도전, 다른 작전과 고정 도전에는 입문 보스가 적용되지 않는다. 보스전의 단일 안내 줄에서 위험 경고를 우선하고, 안전할 때 합체·필살기 버튼 사용을 알려준다.

일반 보스 피해는 입문 전투를 제외하고 `0.6 + 0.4 × min(1, 작전ID/18)` 배율로 점진적으로 증가한다. 19작전부터 기존 피해와 같다. 폐철도 포격형 보스의 개별 포격 간격은 3초에서 5초로 늘리고, 체력 절반 이후 추가 측면 포격을 제거했다. 공통 원형·십자·봉쇄 패턴은 남는다. 1지역을 제외한 새 지역의 지형·일반 포격·작전 전격은 지역 내 첫 네 작전에서 75%→83.3%→91.7%→100%로 증가한다. 접촉 피해·성장 공식·강화 비용·고정 도전은 이 지역 진입 보정으로 바꾸지 않는다.

회복량을 일괄 삭감하지 않는다. 실제 회복을 회복품/수리 스킬/현장 임무/수리 개조/합체/완성 빌드/지원으로 나눠 합계와 일치시킨다. 최대 체력이 증가하며 생긴 빈 체력을 채운 수리 스킬 회복도 별도 출처로 보인다. 매 진행 틱 시작 시 현재 최대 체력의 50% 미만인 시간을 기록하며 선택창에서 멈춘 시간은 제외한다. 종료 체력이나 누적 회복만으로 전투 내내 안전했다고 판단하지 않는다.

### 회수와 조립

- 포격·자폭 적은 포신, 추격·돌진 적은 구동부, 방패·소환 적은 장갑 회수 진도를 준다. 추격형 1점, 기타 일반 적 3점, 정예 이상 12점이며 12점마다 부품을 떨어뜨린다. 같은 종류의 전장 부품은 묶어서 표시하고 종류별 보유 상한은 12개다.
- 전투 하단 조립 버튼에서 전투를 일시 정지하고 주부품과 보조부품을 하나씩 고른다. 미리보기·취소에는 비용이 들지 않는다. 준비가 됐을 때 탑승을 확정해야 고철과 부품을 사용한다.

- 선택한 두 슬롯에 맞는 회수 부품을 최대 2개 사용하며 한 개당 이번 합체 공격력이 15% 높아진다. 같은 종류를 두 슬롯에 넣으면 두 개가 필요하다. 부족분은 기존 고철 비용에 포함해 제작하고 추가 비용을 받지 않는다. 회수 부품이 없다고 조합이 잠기지 않는다.

보조 포신은 관통탄, 보조 구동부는 이동 배율 +0.15와 범위 +25, 보조 장갑은 탑승 시 최대 체력 18% 보호막을 준다. 기존 현장 개조와 함께 작동한다. 총 9조합은 주기체 3종 × 보조 3종이며, 9개의 독립 원화를 추가했다는 뜻은 아니다. 공통 기체 원화와 조합별 금속 부품을 전투·선택창·전시 카드에 함께 사용한다.

### 다음 판과 전시 연결

결과 화면의 `조립 로봇`에서 해당 판에 쓴 기체별 발동·직접 처치·실제 피해를 비교한다. 전시실의 `내가 조립한 로봇`에는 미제작 조합도 보여 다음 목표를 고를 수 있다. 한 번 만든 기체만 공개 전시 가능하며 기존 대원 전시로 돌아갈 수 있다. 목록·공개 프로필·공유 카드가 같은 외형을 사용한다. 전투 부품·공격력은 다음 판에 이월하지 않는다.

조립 선택은 전투 입력의 robot 필드에 남는다. 서버는 규칙 18로 부품 수급·소비·발동을 재생하고 종료 정산에서 제작 기록을 누적한다. 잘못된 설계 번호, 이동과 섞인 조립 필드, 미제작 기체 전시는 거절한다. 같은 결과를 다시 정산해도 제작 횟수가 중복되지 않는다. 이전 저장의 null 컬렉션은 빈 목록으로 정규화한다. 동일 조건 실력전에서는 기존 합체 제한을 유지한다.
