# 강화·출격 동선과 조립 목표 — 0.41.0 / build 45

2026-11-24. 사용자가 직접 플레이하며 강화·구매 위치와 다음 작전이 분명하지 않다고 지적했다. 이어 로봇 도감이 부품을 모으는 목표가 되길 요청했다.

## 바뀐 동선

- 하단을 `상점 / 강화 / 출격 / 로봇 / 더 보기`로 정리했다. 장비 보관함과 대원 선택은 강화 화면에서, 전시실·출석·길드·주간 도전은 더 보기에서 접근한다.
- 강화 화면은 장착 무기·방어구·모듈·선택 대원의 증가 효과와 실제 비용을 함께 표시한다. 재료가 있으면 기존 검증 명령으로 +1 강화, 부족하면 무료 보급·광고·구매 구성 중 선택한다. 자동 구매나 가격 변경은 없다.
- 홈은 현재 지역의 6개 작전, 완료 표시, 현재 선택, 잠긴 작전을 구분한다. 지도 버튼을 별도로 노출한다.
- 기존 승리 화면의 `다시 출격`은 같은 작전을 재시작했다. 이제 승리하면 바로 다음 해금 작전, 패배하면 같은 작전, 최종 작전 승리면 주간 도전으로 이동한다. 이미 깬 작전 재플레이에서도 해금 범위 밖으로 이동하지 않는다.
- 전체 작전을 완료한 계정은 마지막 작전 홈에서 주간 도전을 바로 연다. 지도에서 이전 작전을 고르면 해당 작전 재출격이 가능하다.

## 로봇 도감

- 10개 조합의 특화형·완성형 미리보기, 역할, 특화 조립 여부를 표시한다. 완성형은 기존 게임의 모습이며 이번에 새 진화나 외형을 추가한 것은 아니다.
- 필요 포신·구동부·장갑을 보여 주고, 획득처에서 해당 적과 현재 접근 가능한 작전을 안내한다. 그 부품을 주는 주요 적이 아직 없으면 운반 적 표식을 안내한다. 매 처치마다 지급된다고 설명하지 않는다.
- 도감과 전투가 `RobotAssembly.Recipe` 하나를 공유한다. 기존 비용과 전투 계산을 바꾸지 않았다. 완성형 화면은 특화형 제작 비용에 **추가되는** 비용이다.
- 조립 목표는 기기 내 설정이며 재실행해도 유지된다. 클라우드 동기화·영구 소유권·상점 재고가 아니다. 유도 포신 설계가 없는 계정에서는 해당 목표가 유효하지 않다. 주간 도전의 지정 기체는 도감 목표보다 우선한다.
- 목표를 정해도 전투 부품이나 로봇을 지급하지 않는다. 출격 후 기존 회수 안내와 설계 선택에서 그 목표를 사용한다. 실제 조립·탑승만 기존 입력 기록 및 서버 재생으로 처리한다.
- 상단의 공용 부품은 강화 재화이고, 포신·구동부·장갑은 판마다 모으는 전투 재료임을 구분한다. 전투 전에는 가짜 누적 보유량을 표시하지 않는다.

## 검증

- .NET 핵심 검사 **137/137 통과**. 로봇 재료 소비·조립·재생·모드 분리 및 경제 검증 포함.
- Android ARM64 IL2CPP QA 빌드 성공. `BuildAndroidNavigationQA`로 별도 `.qa` 패키지를 사용했다.
- Android 화면/동선 자동 검증 **오류 0건**, 캡처 24장. 강화 +1, 미리보기의 재화/해금/진행 불변, 잠긴 설계 선택 방지, 목표 전달, 부품 미지급, 패배 재도전, 승리 다음 작전, 최종 작전의 주간 이동을 확인했다.
- 승리·마지막 작전 화면은 **QA 전용 영수증 fixture**다. 실제 플레이 승률이나 진행 기록으로 해석하지 않는다. 홍보 영상에 해당 결과 화면을 쓰지 않는다.
- 별도로 정식 패키지 출시 후보를 운영 서버에 연결해 실제 전투를 수행했다. 포신 4개를 회수하고 연사 포격 전차 특화형을 제작·탑승했다. 1분 43초·443마리 처치에서 직접 종료한 결과 골드 415·부품 3 정산이 수락됐다. 승리 검증이 아니며 실제 구매는 하지 않았다. 기록은 `release-online-result.png`, 영상의 정확한 촬영 빌드는 홍보 폴더의 `edit-manifest.json`에 구분했다.
- 최종 서명 AAB의 bundletool 검증과 universal APK의 서명 v2·16KB ZIP/ELF 정렬 검사를 통과했다. 최종 APK를 QA 기기에 다시 설치해 버전 45, 서버 동기화, 기존 재화·조립 목표 유지를 확인했다. 설치 중 저장 공간 부족은 이번 촬영 원본을 로컬에 보존한 뒤 기기 사본 정리·재부팅으로 해결했다. 최종 해시는 `docs/reports/navigation041/production-verification.json`에 있다.
- 실물 폰 체감, 사람이 강화·구매·도감을 스스로 찾는지, 도감 때문에 재방문하는지는 아직 확인하지 않았다.
- 동의한 로컬 테스트 기록에는 `screen=robots`, `robot_codex/goal`, 기존 `robot_milestone` 이벤트가 남는다. 이번 작업이 서버 KPI 대시보드에 새 전환율을 자동 추가했다고 주장하지 않는다.

## 배포 경계

이 문서의 0.41.0은 새 출시 후보이며 Play에 제출하지 않았다. 기존 0.40.1(44) 심사·배포 상태와 혼동하지 않는다. 전투 규칙은 30으로 유지, 운영 서버의 최신/최소 버전과 가격·광고·판매 설정은 이번에 변경하지 않았다. 새 버전 공개 확인 전에 45로 강제 업데이트하거나 새 도감이 이미 제공된다고 홍보하지 않는다.

서명 번들은 로컬 `Builds/Android/ScrapGuard-production.aab`, 직접 설치용은 `Builds/Android/ScrapGuard-production-45.apk`에 있다. 최종 AAB 106,121,556바이트, APK 106,528,847바이트다. 이 파일들은 저장소에 올리지 않는다.

검증 캡처는 `docs/reports/navigation041/`, 전체 원본은 로컬 `TestResults/Navigation041FinalAndroid/`에 있다. 홍보 초안은 `Store/Promotions/robot-codex-041/`에 별도로 준비했다.
