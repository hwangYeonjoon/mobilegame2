# 0.8 — 첫 플레이 안내와 루크 전용 의상

## 0.19.3 준비 — 재화 이미지·상점·첫 플레이 개선 (2026-11-05)

로컬 소스와 macOS 미리보기에 반영했다. 현재 룬테스트의 0.19.2/code 21, 운영 서버, 상품 가격·보상량·전투 규칙은 변경하지 않았다. 이번 UI를 포함한 Android AAB는 아직 다시 만들지 않았으며, 앞서 생성한 code 22 AAB에는 이 변경이 들어 있지 않다.

- 내장 image_gen으로 만든 투명 아틀라스 `Assets/Resources/Art/CurrencyIcons-v1.png`를 골드 동전 / 민트색 동력 보석 / 강철 부품으로 분리해서 사용한다. 상단 보유량, 보급 상점, 구매 확인, 상품 구성, 전투 결과에 적용했다. 프롬프트는 `ArtSource/CurrencyIcons-v1.prompt.txt`에 보관한다.
- 상점은 `의상 · 스타일 / 성장 · 장비 / 보석 · 광고`로 나눈다. 성장 탭은 재료·확정 장비로 구분하고, 광고 부품 보상을 보석 탭 맨 위에 배치했다. 탭 이동·구매 후 복귀에서 목록의 스크롤 위치를 유지한다. 장비 관리·판매 이동 버튼도 제공한다.
- 재화 구매 확인은 비용·현재 보유량·구매 후 잔액 또는 부족 수량을 함께 표시한다. 골드 부족과 보석 환불 조정 상태에서도 구매 버튼을 막는다. 최종 구매 가능 여부·차감은 기존 명령 처리의 검증이 결정한다. 현금 상품 구성 화면은 제안 가격을 실제 판매 가격처럼 강조하지 않으며 Google Play에서 실제 가격을 확인하게 한다.
- 초보 안내는 지금 할 일과 바로 실행 버튼을 위에 배치하고, 아래에 전체 5단계 진행 상태를 표시한다. 전투 안내에는 어두운 바탕을 적용하고 보스 정보가 표시될 때 안내를 숨겨 겹침을 피한다.
- 플레이어 위치 표식, 위험 예고 영역 내부 이동 안내, 준비된 필살기 버튼의 완만한 강조를 추가했다. 위험 표식은 색 외에 문구로도 안내하며 전투 판정·예고 영역 자체는 변경하지 않는다.
- 의상 획득 화면에 전투 크기 전환과 수집→장착→전시 안내를 추가했다. `이 모습으로 출격 준비`는 의상 장착이 성공한 뒤 대원 선택을 실행한다. 전시 대표 대원 변경은 별도 버튼으로 선택한다. 미리보기는 보유·재화를 변경하지 않는다.
- 전투 결과는 골드·보석·부품 아이콘과 증가량을 나눠 표시하고 재화별 색상을 유지하며 나타난다.

검증: macOS 개발 미리보기 빌드 성공. `-shopPolishSmoke`를 별도 로컬 프로필·360×800 화면으로 실행해 19개 화면을 캡처하고 **런타임/버튼 검사 오류 0건**을 확인했다. 부품 구매 차감, 의상 구매·장착·출격 대원 선택·전시, 이미 보유한 의상 중복 차감 방지, 미리보기 상태 불변, 골드 부족 버튼, 장비 스크롤 복원, 위험 안내 진입/해제를 확인했다. 보고서 `TestResults/ShopPolish/report.txt`. 위험 배치와 전투 승리 결과는 화면 검증용 합성 조건이며 실제 플레이 클리어·서버 검증·Google 구매를 검증한 것이 아니다. Android 실기기 터치·장시간 성능 검증은 남아 있다.

0.17의 첫 후속 후보였던 스파크 `태양로 기술자`와 아이리스 `심해 탐사자`는 이제 0.18에 구현되어 판매 목록에 포함된다. 개발 속도와 구매/보유 데이터를 보고 순서와 간격을 조정한다. 매번 능력치를 높이거나 기존 의상을 퇴출하지 않는다.

수요 판단은 신규 구매 전환, 대원별 의상 보유·장착, 체험→구매 경로, 무료 보석 잔액과 수집 소요 기간을 함께 본다. 의상 수를 늘리는 것만으로 장기 매출을 보장하지 않는다. 0.19에서 별도 동의 기반 체험→구매, 현재 보유/장착률, 보석 수급 집계와 로컬 대시보드를 추가했다. 실제 이용 데이터는 운영 서버 연결 후 축적한다.

### 새 의상 추가 규칙

1. `Outfits`의 끝에 ID·상품 키·전용 대원·컬렉션·원화 이름·설명·연출 이름을 추가한다. 기존 ID를 재배열하거나 다른 상품에 재사용하지 않는다.
2. 2×2 투명 원화와 고유 Unity meta GUID를 추가하고 `OutfitMark`, `OutfitVisuals`, 지원 연출을 연결한다. 기본 탄환 이외의 상태 표시와 적 공격 예고를 보존한다.
3. 구매·중복·기존 의상 재장착·저장 복원·실제 전시·리플레이 동일성을 검증하고 작은 화면과 Android에서 확인한다. 스모크 구매 재화는 카탈로그 개수에 따라 계산한다.
4. 새 ID를 이해하는 앱·서버 버전을 같이 배포한다. 연출만 변경할 때에는 전투 규칙 버전을 올리지 않는다.

### 0.17 검증

코어 81/81, 서버 284개, Unity EditMode 109/109 통과. `TestResults/Style017/report.txt`의 구매·장착·전시·기본 외형 비교·지원·비공개 지원·360×800 UI 스모크는 오류 0건이다. 신규 3종의 화면 캡처를 직접 확인했다. macOS 미리보기와 Android APK를 빌드했고 `TestResults/apk-017-verification.json`에서 패키지·code 17·서명·16KB ZIP/ELF 정렬·FileProvider를 확인했다. Android 실기기 성능·터치와 실제 Google 결제/광고는 아직 검증하지 않았다.

Android 빌드는 `unity run . -- -nographics -buildTarget Android -executeMethod ScrapGuard.Editor.ProjectBuilder.BuildAndroid`로 시작한다. `AndroidSharing` 콜백이 Android 플랫폼에서 컴파일되어 로그인 라이브러리와 공유 설정을 넣어야 하므로 macOS 대상으로 시작한 세션에서 `BuildAll`을 호출하지 않는다.

이하 0.8 최초 의상 도입 기록이다. 현재 수량·데이터·버전은 위 0.17 내용을 따른다.


## 적용 범위

기존 5명·7지역 42작전·도색 10종을 유지하고, 독립된 의상 1종과 첫 플레이 안내를 추가한다. 도색의 지역 ID를 의상에 재사용하지 않는다. 실제 Google 결제·광고 SDK는 이번 작업 범위에 포함하지 않으며 여전히 미연결이다.

## 중장비 정비사

- 루크 전용. `outfit_heavy_engineer`를 보석 600개로 확정 구매한다. 가격은 프로토타입 밸런스 값이다.
- 중장갑, 리벳 대포, 크레인으로 기본 도색과 다른 실루엣을 제공한다. 대기·이동·사격·필살기 4자세를 사용한다.
- 구리빛 탄환과 포구, 기어 충격파, 길드 지원 등장 연출을 추가한다. 공격력·체력·피격 범위·스킬 판정은 변하지 않는다.
- 구매 후 별도 장착한다. `selectedOutfit=1`이어도 보유권이 없거나 대원이 루크가 아니면 적용하지 않는다. 해제해도 보유권과 기존 도색 선택은 보존한다.
- 상점의 스타일 탭에서 의상실을 연다. 체험 영역을 드래그해 이동하고 사격·필살기·지원 등장 버튼으로 연출을 확인한다. 체험은 `GameState`, `Economy`, 네트워크, 리플레이에 접근하지 않는 별도 컴포넌트다. 출격 티켓, 재화, 점수, 보상은 발생하지 않는다.
- 루크의 정비소·대원 목록·전투·전시실·공개 프로필·길드 지원·주간 기록에 적용한다. 주간 기록은 최고 기록을 낸 출격 당시 의상을 보관한다. 비공개 지원 대원의 의상은 수신자에게 보내지 않는다.
- 이동 자세는 정지/보행 프레임 교대, 사격/필살기는 해당 이벤트의 프레임 전환이다. 뼈대 애니메이션이나 3D 모델은 아니다.

## 첫 플레이 안내

정비소의 `초보 안내`에서 언제든 열 수 있으며, 처음 들어오는 계정에는 안내를 표시한다. 안내를 닫아도 다른 메뉴를 자유롭게 이용할 수 있다.

1. 실제 이동 거리 120 이상: 화면 드래그와 자동 공격 안내.
2. 실제 필살기 1회 사용: 처치로 충전하고 버튼으로 발동.
3. 성공한 첫 장비 강화: 장착 무기 관리로 연결.
4. 첫 개조 완성: 조합 도감으로 연결. 예시는 리벳 탄막 Lv.3 + 신속 장전 Lv.2.
5. 작전 6 클리어: 첫 지역 정복과 다음 지역 지도 연결.

전투 중에는 작전 1에 상황별 안내 문구를 표시한다. 전투 관련 진척은 정상 정산한 시뮬레이션에서만 저장하며, 서버 계정은 서버가 재생한 리플레이를 사용한다. 단순 안내 열기나 클라이언트의 승리·처치 수 신고로 달성할 수 없다. 강화 실패와 경계에 막힌 이동 입력은 진척으로 인정하지 않는다. 안내에는 별도 재화 보상을 붙이지 않았다.

기존 계정은 저장 내용을 유지한다. 이전 전투 경험이 있는 계정에 첫 안내를 강제로 띄우지 않고, 장비 레벨과 기존 개조 보고서로 확인 가능한 단계만 이전한다. 과거 이동·필살기를 확인 없이 달성 처리하지 않는다.

## 데이터와 서버

- `GameState`: `selectedOutfit`, `guideVersion`, `guideIntroSeen`, `guideMoved`, `guideUltimate`, `guideUpgrade`, `guideMod`.
- 명령: 기존 `cosmetic_buy`에 상품 추가, `outfit_equip`의 `skin` 필드에 의상 ID 0/1 사용, `guide_seen`은 안내 열람만 기록.
- `PublicProfile`, `GuildMember`, `SupportSnapshot`, `RankEntry`: `outfit` 필드. 이전 데이터는 0으로 해석한다.
- `weekly_records.outfit INTEGER NOT NULL DEFAULT 0`를 기존 점수를 삭제하지 않고 추가한다. 초기화 재실행도 안전하다.
- 구매·보석 차감·명령 재시도는 기존 서버 트랜잭션과 원장을 사용한다.
- 게임 버전 0.8.0 / Android versionCode 8. 판정 변화가 없으므로 전투 규칙 버전은 7을 유지한다.
