# 0.32 구매와 무료 성장의 진행 차이 검증

> 후속 구현과 28일 측정은 [0.33 반복 도전·무료 성장 경로](17-robot-week-and-free-growth.md)를 참조한다. 이 문서의 0.32 측정은 당시 조건의 이력으로 보존한다.

대상은 **0.32.0 / build 35 / 전투 규칙 23**이다. 게임의 가격·성장·보상·전투 규칙과 운영 서버·Play 트랙을 바꾸지 않고, 구매가 진행에 주는 영향을 측정한다. 실제 결제·광고 호출은 없다. 아래 봇 결과는 사람의 재미, 불쾌감, 구매 의향을 측정한 결과가 아니다.

## 검증 결과와 판단

**성장과 구매가 진행을 돕는 방향은 유지할 수 있다. 다만 유료 구매의 추가 효과는 일관되지 않으며, 구매 만족감이나 장기 공정함이 검증된 것은 아니다.** 신규 계정 14일·하루 최대 6회 출격으로 9개 조건 × 조작 2종 × 시드 3개, **54경로·3,543판**을 측정했다. 본 측정 48경로·3,145판 뒤, 무료 경로의 구매 순서 편향을 확인하려고 보급 우선 조건 6경로·398판을 추가했다. 예비 96판은 이 숫자에 포함하지 않는다.

아래는 **자연 조작 봇**의 14일 종료 결과다. 각 행은 같은 시드 3개이며 사람의 승률이 아니다. 완료 작전은 중앙값과 범위다. 보석을 쓰지 않는 대조군도 골드·부품 강화, 출석·임무·무료 패스, 실패 보상·반복 작전을 이용한다.

원화는 실제 Google 결제 금액이 아닌 코드의 상품 제안가 합계다. 남은 유료 보석을 모두 소비했다고 계산하지 않는다. 무료 보석도 함께 소비하며, 유료 경로의 모든 재료가 현금에서 나왔다고 해석하면 안 된다.

- **무료 진행 경로가 있다.** 위험 회피 봇은 상품 미구매를 포함한 모든 조건에서 42작전을 3/3 완료했다. 자연 조작도 무료 보급·광고 경로에서 후반을 완료했다. 이 모델에서는 유료 결제가 유일한 통과 수단이라는 결과는 나오지 않았다.
- **무료 보석의 사용 순서가 중요하다.** 둘 다 구매하는 무료 경로에서 패스 우선은 40/32/42작전, 보급 우선은 40/42/42작전까지 완료했다. 유료 둘 다 경로의 차이는 전자 대비 +2/+10/0작전, 후자 대비 +2/0/0작전이다. 무료 경로에 패스 저축만 가정하면 유료 진행 차이를 과장한다. 세 시드만으로 보급 우선이 모든 이용자의 최적 전략이라고 정하지는 않는다.
- **현금 충전의 추가 가치는 아직 안정적이지 않다.** 보급 유료 경로는 무료 보급 대비 같은 시드의 최종 완료 작전이 −4/0/0이다. 패스 유료 경로는 무료 패스 대비 −2/+16/−7이다. 강화로 처치·경험치·장비 획득 경로까지 달라지므로 항상 더 빨리 깨지는 않는다. 유료 둘 다와 무료 보급 우선 경로가 모두 42작전을 완료한 두 시드의 활동 시간 차이도 +18.5분/−24.7분으로 엇갈린다. 미완료 시드에 가상의 완료 시간을 넣어 평균 절약 시간으로 제시하지 않는다.
- **로봇 재미를 더 준다는 증거는 부족하다.** 같은 작전 첫 도전의 로봇 탑승은 대체로 5회로 상품별 큰 차이가 없다. 처치 속도와 성장 레벨도 함께 보존했지만, 구매로 더 멋진 로봇을 만들고 다시 하고 싶어졌는지는 이 수치로 확인할 수 없다.
- **장기 보급 비용은 별도 과제다.** 42개 최초 완료 보석은 총 2,100개로 유한하다. 모델에 포함한 반복 수입의 상한은 출석 주 150 + 임무 주 210 = 주 360보석이며, 매일 보급은 주 700보석이다. 최초 보상 소진 뒤에는 이 두 수입만으로 매일 구매할 수 없다. 다른 무료 수입·콘텐츠와 강화 상한은 별도 고려가 필요하다. 매일 사야 한다는 뜻이나 장기 과금액 예측은 아니다.

이번에는 **가격·상품 활성화·보상 수치를 조정하지 않았다.** 무료 보급과 강화 경로를 안내하고, 구매가 필요한 것처럼 느껴지는지와 구매 후 실제 강화·전투 경험을 사람에게 확인하는 것이 다음 판단 근거다. 패스에는 의상 가치도 있지만 이 전투 모델은 외형 만족도를 가격으로 환산하지 않는다. 아직 "공정한 BM 검증 완료"나 "돈을 쓰면 반드시 더 재미있다"고 홍보할 근거는 없다.

전체 표와 시드별 짝 비교는 [자동 생성 보고서](reports/purchase032-calendar.md), 원장·출격 전 장비·달력별 상태·판별 결과는 [압축 원본](reports/purchase032-calendar.json.gz)에 보존했다. 18·30·42작전 진입 장비는 도달한 경로만 집계한다. 많이 실패해 강화가 쌓인 무료 경로가 유료 경로보다 진입 공격력이 높을 수도 있으므로, 도달자 중앙값을 전체 이용자 평균이나 구매의 단독 효과로 해석하지 않는다.

검사 결과: 구매 경로/테스트 프로필 C# 검사 **20개**, 독립 원장·집계 Python 검사 **20개**, 기존 성장 검사 **15개**, 코어 **117개**, 기존 경제 집계 검사 **10개** 통과. 자료 변조, 누락 경로, 다른 조건의 자료 병합, 중복 병합, 미도달을 0으로 채우는 오류를 확인했다. 이번 변경은 측정 도구와 문서뿐이어서 Unity·Android·서버를 다시 빌드하거나 실행하지 않았다. 이전 빌드 결과와 이번 검사 결과를 혼합하지 않는다. 사람·실물 폰 검증은 여전히 미실시다.

## 먼저 정한 비교 조건

- 신규 계정부터 14일, 하루 출격 기회 6회, 최대 42작전. 모든 경로에 같은 달력과 출격 기회를 준다. **같은 총 플레이 분수는 아니다.** 전투 시간, 판 사이 30초, 가정 광고 1회당 30초를 따로 합산한다.
- 출석·일일 임무·무료 작전 패스는 **모든 경로**에서 실제 달성한 만큼 받는다. 일일 한도는 날짜를 정상적으로 넘겨 갱신하며 실패한 명령은 보상을 주지 않는다. 매일 임무를 완료했다고 가정하지 않는다.
- 모든 경로는 분산 강화, 실제 획득 장비의 등급 개선과 합법적인 강화 이전을 사용한다. 무기 종류는 같은 등급이면 유지한다. 현장 임무와 로봇 선택도 같은 봇 규칙을 쓴다.
- 자연 조작과 위험 회피 조작을 각각 관찰한다. 두 봇은 이동 방식 등이 다르므로 회피 여부만 다른 대조군이라고 부르지 않는다. 같은 조작 안에서 시드 17·41·71을 구매 조건별로 짝짓는다.
- 다음 작전을 두 번 연속 실패하면, UI의 반복 작전과 같은 **가장 높은 완료 작전**을 한 번 재도전한다. 반복도 6회 중 한 회를 쓰며 실제로 질 수 있다. 이전 작전을 승리로 주입하거나 최초 클리어 보석을 중복 지급하지 않는다.
- 최초 도전과 재도전은 작전·시도 번호로 같은 시드를 사용한다. 반복 파밍은 별도 시드 계열이다. 구매와 승패로 강화·획득 장비·전투 경로가 달라질 수 있다.
- 42작전을 완료하면 추가 소비·출격을 중단한다. 남은 날짜는 완료 시점 상태로 표시한다. 완료한 사람에게 14일 구매를 억지로 채우지 않는다.

보급과 패스를 함께 쓰는 본 측정 경로는 **패스 우선**이다. 무료 경로에서는 900보석을 모으는 동안 보급을 사지 않는다. 추가 민감도 측정 `both_free_kit_first`는 보급부터 구매한다. 두 구매 순서를 비교해도 의상·대원 구매나 모든 절약법을 대표하지는 않는다. 무료 보석을 성장에 쓰면 외형에 쓸 보석이 줄어드는 기회비용은 잔액·소비량으로 남기지만 만족도 수치로 변환하지 않는다.

`none`은 **보석을 쓰지 않는 대조군**이며 무과금 이용자 전체를 대표하지 않는다. `kit_free`·`pass_free`·`both_free`도 실제 충전이 없는 무과금 경로다. 신규 안내·지역 수집·길드·이벤트의 추가 보상, 대원 변경, 다른 보석 상품과 지역 공방 성장까지 모델링한 결과는 아니다.

충전은 `CommerceCatalog.SmallestPack`으로 그 시점의 부족분을 채우는 최소 크기 상품을 선택한다. 남는 보석은 보유하며 다음 구매에서 사용한다. `PremiumWallet`의 **무료 보석 우선 소비**를 그대로 사용해 무료 획득·무료 소비·유료 충전·유료 소비·유료 잔액을 분리한다. 가장 싼 상품 조합을 미리 계산하는 전략은 아니다. 원화 합계는 코드에 있는 **제안가**이며 실제 Play 가격이나 실결제 금액이 아니다.

## 원장과 해석 기준

C# 측정기는 실제 경제 명령과 `Combat`/`FinishCampaign`을 사용한다. 별도 Python 집계기는 원장 연속성, 보석 출처, 상품 가격·지급, 무료 우선 소비, 일일 구매·광고 한도, 달성 전 패스 수령, 미래 작전 개방, 중복 최초 보상, 전투 정산, 파밍 정책, 시드 짝, 날짜별 출격 수와 시간을 검사한다. 출격 전 장비와 능력치도 원본에 남긴다.

다음 세 가지를 분리해 읽는다.

1. **성장 상품 사용 대 미사용:** 무료 보석 소비 자체가 진행에 주는 영향.
2. **동일 상품의 유료 충전 경로 대 무료 보석 경로:** 구매 시점과 구매 횟수의 차이. 현금 충전의 추가 영향을 판단할 때는 이 비교가 더 적합하다.
3. **광고 대 무광고:** 추가 재료뿐 아니라 가정 광고 시청 시간까지 함께 비교.

같은 목표를 **두 경로 모두 완료한 시드만** 반복 횟수·일수 절감으로 계산한다. 한 경로만 완료한 경우는 별도 건수로 남긴다. 미도달은 장비 0, 승률 0, 예상 완료 시간으로 채우지 않는다. 세 시드의 결과로 결제가 필수라거나 과금 압박이 없다고 단정하지 않는다. 14일 예산 안에 후반에 도달하지 못했다면 그 경로의 후반 난이도는 미검증이다.

같은 작전 첫 도전의 로봇 탑승 횟수, 분당 처치, 종료 스킬 레벨도 별도로 본다. 이는 성장으로 어떤 전투 기회가 생겼는지 보는 보조 지표다. 더 빨리 승리하면 탑승 횟수가 줄 수도 있으므로 횟수 증가 자체를 재미로 환산하지 않는다.

## 사람에게 확인할 항목과 안전한 테스트 보석

실제 참가자는 아직 없다. **기존 수동 체험 APK**를 사용하며 자동 QA APK를 건네지 않는다. 이번 측정 도구는 앱 동작을 변경하지 않으므로 새 Android 빌드가 필요하지 않다.

```sh
dotnet run --project Tools/CoreChecks -- --purchase-study-profiles TestResults/PurchaseStudy032
dotnet run --project Tools/CoreChecks -- --purchase-study-clone /local/qa-profile.json TestResults/PurchaseStudyCheckpoint
```

첫 명령은 신규 상태의 0·100·1,000 테스트 보석 프로필을 만든다. 두 번째는 전투를 끝낸 테스트 전용 프로필을 같은 진행의 대조본과 +1,000 테스트 보석본으로 복제한다. 원본, 날짜, 장비, 작전, 구매 한도, 기록 동의를 바꾸지 않는다. 활성 전투나 테스트 표시가 없는 입력, 기존 출력 덮어쓰기는 거절한다. 운영 저장 파일에는 적용하지 않는다. 프로필은 개인정보를 포함할 수 있으므로 `TestResults/` 밖이나 git에 올리지 않는다.

진행자가 수동 `.qa` 앱을 종료하고 해당 앱 전용 `qa-profile.json`에 선택한 복사본을 넣는다. 기존 QA 파일과 `.bak`은 별도로 보관하고, 새 프로필이 정상 로드됐는지 재화·작전으로 확인한다. 운영 앱 패키지에는 접근하지 않는다. 앱 내 기록 동의는 참가자가 선택하게 한다. QA 이벤트는 운영 사용자 지표로 집계하지 않으며 아래 관찰표를 별도로 작성한다.

- 첫 15분은 추가 보석 없이 관찰한다. 실패했을 때 재도전·강화·반복·상점·종료 중 무엇을 먼저 선택하는지 적는다.
- 비교 지점의 진행을 복제한 뒤, 대조본과 테스트 보석본을 참가자마다 다른 순서로 사용한다. “무료 테스트 보석이며 실제 결제는 없습니다”라고 알리고 구매를 요구하지 않는다. 순서와 이전 조작 경험을 기록한다. 같은 저장 지점이어도 전투 난수와 사람 조작은 동일하지 않다.
- 구매 여부·상품·이유, 구매 후 실제 강화·장착 여부, 다음 출격과 로봇 탑승, 마지막으로 기억나는 장면을 기록한다.
- 테스트 보석을 주기 전과 후에 “계속하려면 구매가 필요하다고 느꼈는지”, “무료로 할 수 있는 다음 행동을 알고 있는지”를 각각 묻는다. “재미있어졌다”는 답과 실제 재출격을 구분한다.
- 무료로 준 보석을 쓰는 행동을 현금 구매 의향이나 전환율로 계산하지 않는다. 원화 제안가를 제시했다면 제안임을 알리고 가격 이해도에 대한 답으로만 기록한다.
