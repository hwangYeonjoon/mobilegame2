# 0.5 지역과 작전 확장

## 실제 구현

- 일반 작전 30개: 고철 정비소 / 폐철도 / 오염 처리장 / 냉각 시설 / 중앙 공장, 지역당 6개.
- 각 지역 3·5번째 작전은 시간 생존, 나머지는 최종 보스 처치. 첫 튜토리얼 180초, 일반 작전 210~270초, 보스 처치 유예 최대 60초.
- 지역 지도에서 잠긴 작전도 목표·보상·적 유형을 확인할 수 있다. 잠긴 작전은 출격할 수 없다.
- 기본 4종 몬스터 아트와 4프레임 애니메이션은 유지하고 추격·돌진·포격·자폭·방패·소환 행동을 조합한다. 색·유형 기호·돌진/자폭 예고로 구분한다. 독립된 몬스터 원화 6종을 제작한 것은 아니다.
- 지역별 보스는 돌진 / 포격 / 범위 폭발 / 방패 / 소환을 사용한다. 포격 보스는 체력 절반 아래에서 다중 포격한다.

| 지역 | 맵과 실제 규칙 |
| --- | --- |
| 고철 정비소 | 기존 정유 공장 이미지 위 작업대 구조물. 캐릭터와 적의 이동 충돌, 단순 우회 이동 |
| 폐철도 | 바닥 패널·침목·철로·화물 구조물. 두 철로를 번갈아 예고 후 포격 |
| 오염 처리장 | 폐수조·오염 웅덩이. 웅덩이에 머무르면 주기 피해 |
| 냉각 시설 | 냉각 패널·배관 구조물·얼음 구역. 구역 안에서 가감속 관성 |
| 중앙 공장 | 서로 반대 방향의 컨베이어·설비. 벨트 위 이동 보정과 가로 레이저 예고 |

새 배경은 프로젝트의 Unity UI 도형으로 구성했다. 색 변경뿐 아니라 배치와 지형 판정이 다르다. 스크롤하는 대형 월드나 방 단위 이동, 파괴 가능한 장애물, 엄폐 탄환 충돌은 아직 없다. 작업대는 이동을 막으며 아군 탄환은 통과한다.

## 데이터 확장 방법

`Assets/Game/Core/Campaign.cs`가 앱과 서버에 함께 컴파일된다. 작전 정의에 ID·지역·배치·목표·시간·적 구성·난이도·보상·최초 장비를 모은다. 새 작전을 추가할 때 해금 상한·프로필 분모·지도·보상은 `Campaign.Count`와 정의를 사용한다.

현재는 패키지에 포함된 데이터다. 서버 관리 화면에서 실시간으로 작전을 배포하거나 원격 JSON만으로 추가하는 기능은 없다. 새로운 지역 행동은 코드/아트 추가와 앱·서버 동시 배포가 필요하다. 기존 작전 ID는 삭제·재정렬하지 않고 뒤에 추가한다. 앞으로 원격 콘텐츠를 도입한다면 콘텐츠 버전·서명·구버전 호환·진행 중 작전 스냅샷부터 설계한다.

## 진행과 경제

- 기존 0~4 클리어 ID와 지급 이력 유지. 이전 5탄까지 완료한 계정은 작전 06을 이어서 시작한다. 이전 명칭 일부는 새 지역 구성에 맞게 변경된다.
- 작전 05 완료 시 코어 균열 해금은 유지한다. 기존 5개 완료 칭호도 회수하지 않는다.
- 최초 클리어 보석 50개와 정의된 장비, 재도전에는 최초 보상 없음. 30개 최초 보석 합계 1,500개, 기존 5개 완료 계정의 추가분은 1,250개.
- 성공 골드 `1500 + ID × 90`, 부품 `10 + floor(ID / 2)`. 최종 작전 기준 골드 4,110·부품 24. 보관함이 가득 차면 최초 장비 대신 부품 30개.
- BM 상품·구글 결제·광고 SDK는 변경하지 않았다. 실제 현금 구매는 미연결이다. 보석 공급량이 늘었으므로 레이 해금 1,200보석 등은 출시 전 수급 밸런스를 재검증한다.

## 호환과 검증

전투 규칙 버전 5. 이전 규칙의 진행 중 전투는 서버에서 정산을 거부하고 취소 후 재출격해야 한다. 기존 계정·장비·길드·주간 보상 이력은 유지한다. 코어 균열은 캠페인 지형과 분리한다.

규칙 검사에는 30작전 순차 해금·마지막 경계·최초 보상 중복 방지·기존 계정 이전·30작전 입력 재현·지형 충돌/피해/관성/벨트·돌진/포격/자폭/소환 예고를 포함한다. 실행 결과와 빌드 검증은 아래에 기록한다.

밸런스 수치와 적 외형은 프로토타입이다. 자동 테스트의 성공은 30개 작전 모두의 재미나 사람의 클리어 가능성을 보장하지 않는다. 실제 Android의 가독성·터치·성능과 성장 단계별 클리어율을 확인해야 한다.
